# Telkit·LiveKit 선택형 전화 시험

2026-11-12 최신 변경과 최종 검증은 [전화 인계](../../../docs/PHONE_AGENT_LATEST_HANDOFF.md)를 기준으로 합니다. 아래 날짜별 실패·이전 테스트 수는 당시 이력입니다.

기본 MOCK 도구에 실제 SIP 음성을 연결하는 독립 adapter입니다. 제품 Spring 서버의 `app.mode=LIVE` 차단·공개 `/api/v1` 계약·Android는 변경하지 않습니다. 테스트용 예약 정보를 사용하고 실제 연락처는 비공개 설정에만 둡니다.

단일 Linux 서버 배포는 [배포 안내](../deploy/README.md)를 따릅니다. API·worker가 같은 영속 DB를 쓰며 기본은 MOCK, worker는 명시적인 LIVE 검증 후 실행합니다.

## 흐름

브라우저 예약 승인 → `/api/live/dial` → SQLite 통화 claim → LiveKit named agent dispatch → Telkit SIP 발신 → 식당 음성 → STT → LLM·예약 도구 → TTS → 식당으로 전달합니다. Telkit은 음성 통신을 담당하며 텍스트는 LiveKit STT가 생성합니다.

수신은 Telkit → LiveKit inbound trunk → 개별 room/agent dispatch → 허용한 발신자·trunk 확인 → 기존 예약 식별 → 변경 요청 저장 순서입니다. 사용자 승인과 식당의 변경 확정을 모두 확인한 뒤 새 시간을 적용합니다.

## 설치와 비공개 설정

Python 3.12 환경에서 확인했습니다. 저장소 루트에서 실행합니다.

```bash
python3.12 -m venv work/voice-venv
work/voice-venv/bin/pip install -r prototypes/phone_agent/voice/requirements.txt
cp prototypes/phone_agent/voice/.env.example work/phone-live.env
chmod 600 work/phone-live.env
```

실제 키는 채팅·Git에 넣지 않습니다. 환경 파일은 단순 `KEY=VALUE`만 읽으며 셸 표현식을 실행하지 않습니다. `PHONE_ENV_FILE`로 경로를 바꿀 수 있습니다. `work/`와 `data/`는 Git 제외입니다. 비밀값 파일은 권한 600, Telkit 파일 폴더는 700을 사용합니다.

- LiveKit Cloud 프로젝트의 WSS URL·전용 API key/secret·SIP URI를 입력합니다. 키 생성과 계정 약관은 사용자 승인 후 진행합니다.
- Telkit 본인인증·카드 등록과 번호 구매는 공식 계정 흐름에서 완료합니다. 구매 전 번호·30일 갱신 비용을 명시해 승인받습니다. 이 adapter는 계정 생성·번호 구매·카드 등록·SIP credential 회전을 하지 않습니다.
- 구매한 번호와 ID, Telkit API key, 발급한 SIP username/password를 설정합니다. 기존 로컬 `work/telkit-private/`의 `workspace-key.json`·`sip-credential.json`·`livekit-setup.json`도 읽을 수 있습니다.
- `PHONE_ALLOWED_NUMBERS`는 승인된 국내 테스트 번호의 E.164 목록이고, `PHONE_RESTAURANT_NUMBERS`는 식당 ID→허용 번호의 JSON 객체입니다. 로그인으로 보호된 시험 화면에서 `PHONE_TEST_PHONE_INPUT=true`를 설정하면 승인된 시험 예약에 한해 발신 시 입력한 국내 010 번호를 사용합니다. 번호 소유권은 사용자가 확인합니다.
- `PHONE_MAX_SECONDS`는 30–600, `PHONE_DAILY_CALLS`는 1–10이며 기본은 180초·하루 1회입니다. Telkit 자체 최대 통화 시간도 별도로 설정합니다. 첫 실제 시험에서는 두 경계를 60초로 제한했습니다.

## SIP 준비와 읽기 전용 확인

```bash
work/voice-venv/bin/python -m prototypes.phone_agent.voice doctor
work/voice-venv/bin/python -m prototypes.phone_agent.voice plan
work/voice-venv/bin/python -m prototypes.phone_agent.voice setup --apply
```

`doctor`는 키·번호 없이 준비 상태만, `plan`은 SIP 설정안과 선택한 번호를 표시합니다. 설정안은 공개 공유하지 않습니다. `setup --apply`만 외부 설정을 변경합니다. 이름으로 기존 자원을 대조해 inbound/outbound trunk·dispatch rule을 만들고 각 ID를 즉시 비공개 journal에 기록한 후 선택한 Telkit 번호의 연결을 갱신합니다. 기존 자원이 다르면 자동 덮어쓰지 않습니다. 중단 후 journal과 콘솔을 대조하고 재실행합니다. 동시 setup 프로세스는 지원하지 않습니다.

TLS·SRTP 필수, Telkit 공식 IP와 승인된 수신 번호를 설정합니다. 다만 Telkit 공식 안내상 LiveKit의 IP 제한은 지원팀이 프로젝트에서 활성화하기 전에는 저장만 되므로 강제 적용을 가정하지 않습니다. 승인된 caller allowlist·worker의 trunk/예약 식별 검사는 별도로 유지합니다. setup 후 실제 번호 연결 상태를 조회해 반영을 확인해야 합니다. trunk 생성이나 SIP 설정 성공만으로 수신 통화 성공으로 판단하지 않습니다.

## 실제 시험 실행과 중단

대상·목적·횟수·비용·시간 상한을 승인받은 뒤에만 비공개 파일의 `PHONE_LIVE_ENABLED=true`를 설정하고 두 프로세스를 실행합니다. 음성 SDK가 설치된 같은 Python과 같은 DB를 사용해야 합니다.

```bash
work/voice-venv/bin/python -m prototypes.phone_agent --port 8765
work/voice-venv/bin/python -m prototypes.phone_agent.voice.worker start
```

[로컬 화면](http://127.0.0.1:8765)에서 예약 생성·조건 승인 후 **실제 테스트 전화 걸기**를 누릅니다. 가상 통화 버튼은 외부 전화를 걸지 않습니다. HTTP 화면과 worker health endpoint는 loopback에 바인딩합니다. 이 컴퓨터와 worker가 실행되는 동안만 AI가 연결되며 Cloud 상시 배포는 아닙니다.

중단할 때 worker에 Ctrl+C를 보내고 환경 파일을 `PHONE_LIVE_ENABLED=false`로 되돌립니다. 실행 중 통화는 worker shutdown과 provider 최대 시간으로 종료를 제한합니다. 승인 1회를 실행한 뒤 자동 반복·재발신하지 않습니다. 로컬 DB의 일일 상한은 UTC 날짜 기준이며 DB 삭제·복제나 다른 클라이언트 발신까지 포함하는 사업자 과금 상한이 아닙니다. 사업자 콘솔의 잔액·한도도 확인합니다.

## Soniox 음성 인식 시험

기본 STT는 AssemblyAI입니다. [Soniox v6](https://docs.soniox.com/stt/models)를 비교할 때는
별도 DB·agent 이름과 권한 600의 환경 파일을 사용하고
`PHONE_STT_MODEL=soniox/stt-rt-v6` 및 `SONIOX_API_KEY`를 설정합니다.
`PHONE_MAX_SECONDS=60`, `PHONE_DAILY_CALLS=1`, `PHONE_INBOUND_ENABLED=false`,
`PHONE_TEST_PHONE_INPUT=false`와 등록 시험 휴대폰 1대가 필요합니다.
등록 휴대폰을 사용하는 가상 식당의 새 시험 예약에만 발신할 수 있습니다.
Soniox 키가 없으면 LIVE 시작과 발신을 차단합니다. 기존 SIP·LLM·TTS·AEC는 같은 설정을 사용합니다.

시험 worker는 [Agent text input](https://docs.soniox.com/stt/rt/agent-text-input)을 활성화합니다.
고정된 Soniox 플러그인 1.8.11에 시작 설정과 같은 WebSocket의 텍스트 프레임 전송을 추가했습니다.
RoomIO의 재생 동기화된 출력 뒤에서 발화 조각을 받아 SSML을 제거하고, 재생 종료·중단 시
`end_of_segment`를 전송합니다. LLM의 전체 답변이나 미재생 뒷부분을 미리 보내지 않습니다.
현재 타이밍은 LiveKit의 재생 위치 추정이며 공식 문서가 권장하는 글자별 500–1000ms 선행
전송을 정확히 구현한 것은 아닙니다. AEC는 계속 사용합니다. `agentTextInput` 진단에는
전송 조각·문자·종료·유실·오류 수만 저장합니다. 전송 텍스트에는 Soniox 입력 토큰 비용이 붙습니다.

첫 소개가 들리지 않았다는 실전화 피드백에 따라 시험 worker에 600ms 무음 재생 준비와
DTX 비활성화, 첫 소개 전후의 송신 RTP 카운터를 추가했습니다. 무음은 대화 기록에 넣지 않습니다.
`openingAudio` 카운터는 worker→LiveKit 전송만 보여주며 휴대폰 도달의 증거가 아닙니다.
첫 소개는 TTS 합성을 끝낸 뒤 메모리에 모은 프레임을 재생합니다(최대 합성 대기 6초).
Soniox 시험에서는 소개의 성명을 한 단어로 읽고, 이후 예약 이름 확인은 별도 문맥으로 처리합니다.
2026-11-12 승인된 1회 시험에서 사용자가 소개의 이름이 끊김 없이 자연스럽다고 확인했습니다.
해당 통화는 37초·예약 CONFIRMED였으며, 원음 없이 필터 전후 음량과 송신 카운터만 계측했습니다.
모든 환경의 음질을 보장하거나 기본 AssemblyAI worker를 Soniox로 전환한 결과는 아닙니다.

승인한 통화에서 식당 역할이 말한 가상 이름, 예약 시간, 추가 요금 유무와 금액을 같은 통화의
전사 기록과 대조합니다. STT의 정적 context에는 정답 용어 힌트를 전달하지 않습니다.
Agent text input을 켠 통화는 AI가 실제 말한 내용을 활용하므로 이전 무힌트 시험과 구분합니다.
추가 요금이 있는 답변은 시험 예약이 확정되지 않아야 합니다.
유료 Soniox API 사용료와 Telkit 발신료는 실행 전 확인합니다.

## 기록과 결과 판정

- 승인된 예약 사본·버전·소유 세션·식당 번호 mapping을 검증하고 원자적으로 통화 작업을 선점합니다. 외부 API는 DB transaction 밖에서 호출합니다.
- worker는 room·일회성 nonce·SIP 참가자를 확인합니다. inbound는 허용 번호와 정확한 trunk를 확인한 뒤 한 예약을 식별해야 합니다.
- 모델에는 확인된 예약 이름·일시·필수 조건만 전달합니다. dispatch metadata에 사용자 조건·키를 넣지 않습니다.
- 실제 발화는 LIVE event와 call ID로 로컬 저장합니다. SDK handoff는 대화 근거로 취급하지 않습니다. 원본 음성 녹음은 생성하지 않습니다.
- 결과는 해당 통화의 최근 식당 발화 인용, 이름·일시·인원·추가 비용 0원·필수 조건을 대조합니다. 이름도 실제 인식된 발화에 있어야 합니다. 발화 의미의 해석은 STT/LLM에 의존하므로 완전한 의미 검증을 보장하지 않습니다.
- 미확인·타임아웃·단절은 UNKNOWN이고 자동 재발신하지 않습니다. 실제 결과를 가상 버튼으로 확정하지 않습니다. 진행 중 전체 삭제를 차단합니다.
- 수신 통화의 변경 요청은 사용자 확인 대기이며, 승인 후 같은 통화에서 식당이 변경을 확인하면 새 시간을 적용합니다.
- 로컬 텍스트·예약은 세션 전체 삭제로 지울 수 있지만 공급자 보관 데이터 삭제와 별개입니다. 공급자 보관 정책·운영 알림·자동 만료·crash 이후 외부 통화 대조·outbox는 후속입니다.

## 모델과 검증 상태

### 식당의 수신 회신 — 2026-11-11

`PHONE_INBOUND_ENABLED`는 기본 false이며 발신 `PHONE_LIVE_ENABLED`와 독립적입니다.
수신만 시험할 때는 전자만 true로 하고 worker를 시작합니다. 발신은 계속 차단되며
수신에도 기존 전체 일일 횟수·동시 1통·시간 상한과 허용 번호/trunk 검사를 적용합니다.
현재는 등록된 테스트 식당 번호만 받고 다른 번호·발신번호 비공개는 거절합니다.
발신번호만으로 실제 식당 신원을 인증한 것으로 보지 않습니다.

휴대폰을 식당 역할로 사용한 시험 예약으로 회신을 검증할 때는 수신 worker의
`PHONE_CALLBACK_TEST_BOOKING_ID`에 해당 확정 예약을 지정합니다. 수신 서비스 번호는
`TELKIT_NUMBER`와 일치해야 하며, `PHONE_RESTAURANT_NUMBERS`에 지정된 발신자 번호가
기존 확정 시험전화의 실제 수신 번호와 일치해야 합니다. 이 설정은 기본적으로 비어 있습니다.

전용 binding이 없는 수신은 일반 AI 소개 후 예약자 성함부터 묻습니다. 상대가 제시한 이름·날짜·기존 시간과
식당 mapping이 유일한 LIVE 확정 예약과 일치해야 연결하며 후보를 먼저 읽지 않습니다.
동명이인·복수 후보·불일치이면 임의 선택하지 않습니다. 식별 전 전사는 별도 비공개
영역에 통화당 최근 20개만 두고, 식별한 통화의 기록만 해당 소유자에게 옮깁니다.
이 임시 영역의 자동 만료·운영 보관 정책은 후속 과제입니다.

시간 변경은 실제 같은 통화의 최근 전체 발화 근거와 함께 AWAITING_USER로 저장합니다.
예약을 만든 브라우저 화면 상단에 승인·거절을 표시하고, 비서는 식당에 잠시 기다려 달라고 말한 뒤 최대 20초 동안 결정을 확인합니다. 승인하면 같은 통화에서 식당에 확정을 요청하고 명확한 응답을 받았을 때 새 시간을 저장합니다. 거절은 통화에서 전달하고 기존 시간을 보존합니다. 대기 시간이 지나면 요청을 남겨두고 안내한 뒤 종료합니다.
취소·예약 불가·기타 문의는 NEEDS_REVIEW 회신으로 접수합니다. 취소·예약 불가는
확인 필요 표시와 reviewRequired를 세워 자동 변경 재확인을 막습니다. 원 확정 기록을
취소 완료로 바꾸지 않으며 수동 처리·해결 상태 전이는 아직 없습니다.
일반 문의는 접수 후 짧은 안내를 재생하고 통화를 마칩니다.

해당 소유 세션의 웹 화면은 보이는 동안 실제 통화 기록이 있으면 2초, 가상 모드는 5초 간격으로 DB 상태를 조회합니다.
화면 접수와 실제 사용자 확인은 다르며 휴대폰 푸시·문자·운영 알림은 미구현입니다.
가상 및 네트워크 차단 검사는 실제 수신 성공의 증거가 아닙니다. 수신·사용자 전달
검증 전에는 발신 통화에서 “이 번호로 다시 연락 주세요”라는 안내를 하지 않습니다.

수신 보완 소스 `b2be74a`는 로컬과 EC2 Linux(network=none)에서 기본 36개·음성 94개,
총 130개 검사를 통과하고 배포됐습니다. 기본 양쪽 비활성·worker 중단 상태이며 기존
13개 통화와 마지막 발신 확정 성공은 보존했습니다. 실제 수신과 변경 재확인은 미검증입니다.

### 1인 전용 번호의 기존 예약 문맥

번호 소유권을 검증한 운영자가 `LiveWorkflow.bind_inbound_number(owner, number, trunk_id)`로
기존 예약 소유 세션에 번호를 연결할 수 있습니다. 이 메서드는 HTTP/음성 도구로 제공하지
않으며, 진행 중인 통화에서 새 binding을 만들거나 다른 소유자/trunk로 이전하지 않습니다.
binding은 영속 SQLite에 저장하고 번호·소유 ID를 웹 상태에 공개하지 않습니다.

수신은 [sip.trunkPhoneNumber](https://docs.livekit.io/reference/telephony/sip-participant/)의
실제 서비스 번호와 정확한 trunk, 허용 식당 caller를 함께 확인합니다. 연결된 owner의 해당
식당 LIVE 확정 예약이 유일하면 기존 이름·일시·인원·승인 조건을 미리 불러옵니다. 다른
소유자나 MOCK 예약을 대신 선택하지 않습니다. 예약이 여러 건이면 같은 owner 안에서만
식별하고 후보를 먼저 읽지 않습니다. 전용 번호 속성이 누락되거나 일치하지 않으면 거절합니다.

확인된 회신에서는 기존 이름·날짜·시간을 다시 묻지 않고 문의 목적을 받습니다. STT에는
그 예약의 이름 하나만 보정어로 전달합니다. 변경 제안·승인 상태와 확인 필요 여부도 문맥에
포함하며 변경 완료나 사용자 확인을 주장하지 않습니다. 원 예약·동승 조건과 승인/실제
재확인 경계는 유지합니다. 연락처 저장 이름의 자동 동기화·새 번호 구매·일반 사용자 가입
기능은 아닙니다. 로컬/EC2 Linux(network=none) 142개 검사를 통과한 `b64bb5b`를 배포하고
사용자 선택에 따라 기존 번호를 승인 이름의 예약 소유 세션에 실제 연결했습니다. DB를 다시
열어 binding·원 예약/조건·통화 15건 보존을 확인했습니다. 발신/수신 비활성·worker 중단
상태이며 전용 문맥을 사용한 실제 수신은 미검증입니다.

의존성은 `livekit-agents[silero]==1.8.11`, `livekit-api==1.2.2`, `livekit-plugins-noise-cancellation==0.3.3`입니다. NC 플러그인은 LiveKit Cloud용이며 패키지 라이선스는 LiveKit 서비스 약관을 참조합니다. 공급자 바이너리를 저장소에 복사하지 않습니다. ## 문맥 수락과 종료 음성

새 예약에서 이름을 포함한 직전 예약 요청과 식당의 실제 수락을 연결합니다. “네”, “예”, “알겠습니다”, “예약되었습니다”도 문맥상 수락이며 이름을 다시 말하게 하지 않습니다. 짧은 답은 실제 발화 그대로 근거로 받고, 같은 “네”가 비용 답에도 반복되면 최근 같은 통화에서 예약 요청에 답한 쌍을 찾습니다. 전체 응답을 대조하므로 “네, 다만…”의 앞부분만 인용해 조건을 지울 수 없습니다. 가능 여부·비용·다른 질문에 대한 답만으로 확정하지 않고, 후속 정정·취소·미해결 대기는 UNKNOWN으로 둡니다. 이미 수락한 뒤 잠시 대기했다가 비용/조건 확인이 끝난 경우는 다시 이름을 반복할 필요가 없습니다.

수락의 의미는 모델이 판단하고 서버는 최근 실제 근거·직전 요청·승인 이름/일시/인원/추가 비용/필수 조건을 함께 대조합니다. 들어오는 수락 답변을 고정된 문구 목록으로 제한하지 않습니다. 명확한 부정·조건·대기에는 보수적인 차단 규칙을 유지하며 이 규칙이 모든 한국어 의미를 이해하는 것은 아닙니다. 변경 재확인은 기존 명시적 발화 기준을 유지합니다. 이 보완은 아홉 번째 시험 뒤 가상 회귀 검사로 검증했으며 추가 실전화는 하지 않았습니다.

## 스피커폰 에코 처리 — 실험 옵션

`PHONE_ECHO_CANCELLATION=true`는 통화별 WebRTC APM을 만들고, 음성 인식과 VAD에 전달되기 전의 공통 입력에 적용합니다. 기본은 false이며 비교·복귀할 수 있습니다. 입력/출력을 mono 16 kHz로 맞추고 입력을 10ms 단위로 나눕니다. 출력 PCM은 변경하지 않고 실제 RoomIO 제출 속도에 맞춰 공급해 TTS 생성 시점이 재생 시점보다 크게 앞서는 것을 줄입니다. 중단·일시정지·재개와 재생 완료 이벤트를 전달합니다. 이미 제출한 참조는 중단 직후 돌아올 에코를 위해 잠시 유지합니다.

`PHONE_ECHO_DELAY_MS=200`은 **측정된 SIP 왕복 시간이 아닌 초기 추정값**입니다(0–500ms). 서버 참조는 RoomIO에 제출한 PCM이며 상대 휴대폰의 실제 스피커 재생 시각·음량·전화망 변형은 직접 관측하지 못합니다. 이 구현만으로 완벽한 분리나 끊김 해결을 보장하지 않습니다. [SDK APM](https://docs.livekit.io/reference/python/livekit/rtc/apm.html)의 10ms 프레임·출력 참조·지연 설정을 사용하며 SDK 자체를 수정하지 않습니다.

PCM 참조는 통화별 메모리에 최대 2초만 보존하고 종료 시 비웁니다. AEC용 PCM 참조는 파일로 저장하거나 별도로 외부 전송하지 않고, 처리 오류 시 원래 입력을 전달하며 해당 통화의 AEC를 중지합니다. 기존 NC·adaptive 중단 정책·모델·예약 판정은 유지합니다. 진단에는 처리 프레임 수·오류·참조 넘침·입력 시간축 차이·출력 제출 간격·최대 처리 시간·에너지 비율만 남깁니다. 이 값은 RTP 패킷 지터/손실이나 원격 청취 점수가 아닙니다.

추가 오프라인 검사는 번들 가상 음성에 220ms 지연 에코를 섞어 감소를 확인하고, 다른 가상 발화가 겹칠 때 에너지가 유지되는지 검사합니다. 발화 에너지 유지는 한국어 인식 정확도·명료도 검증이 아닙니다. 실제 스피커폰 통화의 청취 결과는 별도 기록합니다.

2026-11-10 아홉 번째/두 번째 EC2 시험은 이 옵션을 켜고 스피커폰으로 진행했습니다. 42초·60원, 입력 39.8초·STT 최종 5개·AI 중단 메시지 0개·대기 요청 1개·모델/AEC 오류 0개였습니다. 사용자는 끊김 감소와 응답 개선을 보고했습니다. UNKNOWN 저장 후 종료했고 LIVE/AEC를 끄고 worker를 중단했습니다. 로컬·Linux 102개 검사를 통과했습니다. 한 번의 통화이며 지연 초깃값의 적합성·말 겹침 명료도·다른 소음 환경·개선의 단독 원인은 검증되지 않았습니다.
