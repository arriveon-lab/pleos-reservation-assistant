# 전화예약 에이전트 로컬 프로토타입

2026-11-12 최신 변경과 최종 검증은 [전화 인계](../../docs/PHONE_AGENT_LATEST_HANDOFF.md)를 기준으로 합니다. 아래 날짜별 실패·이전 테스트 수는 당시 이력입니다.

계정·전화번호 없이 가상 예약 상태를 테스트하는 독립 도구입니다. 기본 MOCK 실행은 Python 3.10 이상과 브라우저만 필요하며 외부 API를 호출하지 않습니다. 선택형 [Telkit·LiveKit 음성 연결](voice/README.md)을 설치·설정하고 별도로 실행을 승인하면 실제 한국어 전화도 시험할 수 있습니다. 가상 시나리오와 실제 통화 기록은 구분해 표시합니다.

제품 Spring 서버·Android 앱과 별도로 실행합니다. 현재 제품 `/api/v1` 계약·인증·DB migration·LIVE 차단을 변경하지 않습니다. 이 도구의 세션은 로컬 테스트용이며 제품 인증이나 실제 식당 발신자 인증을 대체하지 않습니다.

서버에 설치하려면 [단일 Linux 배포](deploy/README.md)를 따릅니다. EC2에서 API·영속 DB와 MOCK 흐름을 확인했으며 음성 worker는 별도 승인 후 시작합니다.

식당에서 걸려온 수신 회신은 허용 번호·trunk와 이름·날짜·기존 시간으로 예약을 식별한 뒤
시간 변경 요청이나 취소·예약 불가·기타 문의를 저장합니다. 원 예약과 동승 조건은 보존하며
웹 화면은 보이는 동안 5초 간격으로 갱신합니다. 취소·예약 불가는 확인 필요로 표시하고
자동 변경을 막습니다. 실제 수신 시험·휴대폰 푸시·취소 해결 절차는 아직 미완료입니다.

## 실행

추천과 전화의 모의 통합은 저장소 루트에서 실행합니다.

```bash
./gradlew -PincludeAndroid=false :server:bootJar
python3 scripts/mock-agent-integration.py --candidate 2 --scenario REQUIREMENT_UNAVAILABLE --next-scenario ACCEPT --prompt-approval
python3 scripts/mock-agent-integration.py --verify
```

스크립트는 Java 추천 서버와 Python 전화 에이전트를 별도 프로세스로 실행합니다. Java는
인증된 사용자의 추천 목록과 인원·필수 조건을 HTTP로 넘깁니다. Python은 추천 후보의 상호와
전체 주소를 가상 카탈로그와 대조하고 임시 SQLite에 승인과 결과를 저장합니다. 시연 예약
시각은 한국 시간 내일 19시입니다. 식당의 조건 응답과 해당 시각의 예약 가능 여부를
시나리오로 재현합니다.

`--prompt-approval`을 켜면 각 후보와 예약 조건을 보고 `예`를 입력해야 시도합니다. 첫
후보의 필수 조건 미충족 또는 예약 불가가 확인되면 다음 후보를 보여주고 다시 승인받습니다.
`--prompt-approval`을 생략한 실행에서는 각 `--scenario` 옵션이 별도의 가상 승인을 보냅니다.
`--scenario`도 생략하면 후보 선택 화면에서 승인 대기 상태로 끝납니다.
`--verify`는 다음 후보 승인, 미확인 결과 보류, 중복 요청, 사용자별 결과 격리를 검사합니다.

수동 실행 시 두 프로세스에 동일한 `PHONE_RECOMMENDATION_TOKEN` 환경 변수를 설정합니다.
Python은 `--mock-recommendation-catalog`로 가상 파일을 받고, Java는
`app.mode=MOCK`, `app.destination-recommendations.enabled=true`,
`app.destination-recommendations.source=PUBLIC_CATALOG`, `app.destination-recommendations.catalog-path`에 같은 가상 파일 경로,
`app.recommendation-phone.enabled=true`, `app.recommendation-phone.port`를 설정합니다.
클라이언트는 [추천 서버의 승인 계약](../../api/destination-recommendation-draft.json)을 사용합니다.

전화 프로토타입 화면은 저장소 루트에서 아래 명령으로 실행합니다.

```bash
python3 -m prototypes.phone_agent --port 8765
```

[로컬 테스트 화면](http://127.0.0.1:8765)을 엽니다. 기본 DB는 Git 제외 `data/phone-agent-prototype.sqlite3`입니다. 서버는 `127.0.0.1`에만 바인딩하고 임의 Host·다른 Origin·세션 없는 변경 요청을 차단합니다. 별도 DB와 포트를 사용할 수 있습니다.

```bash
python3 -m prototypes.phone_agent --port 8766 --database data/phone-agent-second.sqlite3
```

Ctrl+C로 종료합니다. 같은 브라우저 세션과 DB로 다시 시작하면 상태를 복구합니다. 브라우저 쿠키가 사라지면 새 소유 세션이 생성되며 기존 데이터가 자동 배정되지 않습니다. 실사용자·실제 동승자·연락처 정보는 입력하지 않습니다.

## 화면으로 테스트

### 목적지 웹검색

로컬 전화 화면은 추천 서버의 웹검색 후보와 조건별 근거를 표시합니다. 왼쪽에서 웹으로 조사할
조건을 고르고 **목적지 주변 식당 웹검색**에 지역명을 입력합니다. 웹에서 찾은 근거는
조건별로 가능·불가·미확인·상충으로 표시합니다. 후보 카드의 주소, 후기 요약과 조건 근거에는
출처 링크를 제공합니다.

추천 서버 JAR을 `./gradlew -PincludeAndroid=false :server:bootJar`로 빌드한 뒤, 아래 전화
화면 실행에 `--web-search`를 추가합니다. `OPENAI_API_KEY` 환경 변수 또는 권한이 600인
비공개 `work/openai-web.env`를 사용합니다. 추천 서버가 이미 실행 중이면
`--recommendation-port`로 루프백 포트를 지정할 수 있습니다. 기본 검색 한도는 실행당 1회이며
`--web-max-calls`로 지정합니다. 검색은 폼을 제출할 때 시작합니다.

### 등록 휴대폰으로 실전화 시험

이 화면의 식당 목록은 `--directory`로 읽는 로컬 공개 연락처 목록입니다. 각 항목은
`id`(접두사 `test-`), `name`, `address`, `phone`, `sourceUrl`을 담습니다. 지점과
공개 번호는 예약 카드에 표시됩니다. 시험 발신 대상은 기존 `PHONE_ALLOWED_NUMBERS`의
휴대폰 한 대입니다. 화면에는 그 휴대폰의 끝 네 자리만 표시됩니다.

통화에 사용할 Python 음성 환경에서 아래 명령을 실행합니다. 기본 실행은 미리보기입니다.

```bash
python -m prototypes.phone_agent.voice.console \
  --directory work/test-restaurant-directory.json \
  --env-file work/phone-live.env
```

실제 시험할 때 `--live`를 추가합니다. 미리보기를 켜 둔 상태라면 `--port 8768`을
추가해 별도 화면을 엽니다. 실행기는 음성 worker 등록을 기다리고 화면 주소를 출력합니다.
예약 조건 저장 → 공개 식당 선택 → 예약 요청 만들기 → 승인 → **등록 휴대폰으로 시험전화**
순서로 진행합니다. 마지막 확인에는 시험 대상과 설정된 최대 시간이 표시됩니다. 통화가
진행되는 동안 예약 카드와 대화 기록이 자동으로 갱신됩니다. 결과는 시험 전용 SQLite에
저장합니다. 시험을 마치면 터미널에서 `Ctrl+C`로 화면과 worker를 종료합니다.

공개 식당 목록은 수동으로 검토해 추가합니다. 웹검색 후보 카드는 조사 결과를 보여줍니다.

### 가상 전화와 회신

1. **예약부터 변경까지 자동 시연**을 누르면 별도의 가상 여정을 만들고 예약 생성·승인·수락·회신·변경 승인·식당 재확인을 실행합니다. 19:00 → 19:30 변경 완료와 대화 기록을 확인합니다. 이 시연에서는 재사용 프로필을 만들지 않습니다.
2. 수동 테스트는 왼쪽의 예약자 이름·전체 인원·유아의자·반려동물·접근성·식사 조건을 확인하고 **새 여정 조건 저장**을 누릅니다.
3. 날짜·시간·가상 식당을 선택해 예약 요청을 만들고, 오른쪽에서 조건을 확인해 **이 조건으로 발신 승인**을 누릅니다.
4. 식당 응답을 선택해 **가상 통화 시작**을 누릅니다. 수락·거절·애매한 답변·단절·필수 조건·비용·시간 불일치·ARS를 비교합니다.
5. 확정된 예약의 이름·날짜·기존 시간을 식당 회신 폼에 입력하고 변경 시간을 제안합니다. 같은 식당이어도 여러 예약이 일치하면 자동 선택하지 않습니다.
6. 변경을 승인해도 기존 확정 시간은 유지됩니다. **식당이 변경 수락**을 눌러야 새 시간이 반영됩니다. 재확인 중 단절은 변경 UNKNOWN으로 보존합니다.
7. 새로고침·서버 재시작 후에도 예약·변경·가상 대화가 유지되는지 확인합니다.

한 여정에는 처리 중·미확인·확정 예약을 중복 생성하지 않습니다. 새 시나리오를 독립적으로 비교하려면 새 여정을 저장합니다. 승인 전이나 후에 현재 여정의 조건을 수정하면 기존 요청을 최신 조건으로 조용히 바꾸지 않고 승인·발신을 차단합니다. 수정된 조건으로 새 여정을 만들어 다시 확인할 수 있습니다.

## 사용자와 동승자 정보

- 기본값은 프로필 재사용 저장 미선택입니다. 예약에는 확인된 동승자 조건의 사본을 보관합니다.
- **다음 여정에도 기억하기**를 선택한 뒤 조건을 저장하면 이름과 조건 템플릿을 저장합니다. 식사 관련 상세 텍스트는 재사용 템플릿에서 제외합니다.
- 저장한 조건을 불러와도 입력 초안만 채웁니다. 새 여정을 저장하고 예약을 승인하기 전까지 통화로 사용하지 않습니다.
- 프로필 또는 여정의 조건을 바꿔도 이미 승인한 예약 사본과 확정 내용을 자동 변경하지 않습니다.
- **저장 프로필 삭제**는 재사용 프로필만 지웁니다. 예약과 회신을 위한 사본은 유지합니다.
- **전체 테스트 정보 삭제**는 해당 소유 세션의 프로필·여정·예약·회신·대화·기존 요청 원장을 삭제하고 이전 세션 토큰을 폐기합니다. 다른 사용자의 테스트 기록은 지우지 않습니다.
- 자동 보관 만료와 선택 필드별 삭제는 이 프로토타입에 구현하지 않았습니다. 테스트 후 전체 삭제하거나 별도의 가상 DB를 제거합니다. 실제 운영의 보관 기간은 계획 P01에서 확정하고 구현해야 합니다.
- 프로필 저장·예약 승인·학습 동의를 구분하며, 모델 학습은 수행하지 않습니다.

## 테스트와 계약

```bash
python3 -m unittest prototypes.phone_agent.test_service -v
python3 -m py_compile prototypes/phone_agent/*.py
node --check prototypes/phone_agent/static/app.js
```

Python 테스트는 임시·메모리 DB와 loopback만 사용합니다. `.github/workflows/phone-prototype.yml`이 같은 행동 테스트를 수행합니다. Node는 프런트엔드 문법 검사에만 사용하며 실행 의존성은 아닙니다.

| 검증 범위 | 확인하는 행동 |
| --- | --- |
| 저장 선택 | 프로필 미저장 예약 가능, 재사용 저장 명시 선택, 식사 정보·학습 동의 분리 |
| 조건 사본 | 프로필 수정·삭제 후 예약 보존, 여정 변경·버전 충돌 시 발신 차단 |
| 예약 판단 | 명확한 수락만 확정, 필수 조건·추가 비용·시간 불일치·ARS·단절은 임의 확정 금지 |
| 중복·동시성 | 요청 키 재전송 한 번 반영, 키 변조 충돌, 동시 요청, 한 여정 활성 예약 제한 |
| 소유권 | 다른 세션 예약 접근 불가, 회신 이름·날짜·기존 시간 확인, 여러 후보 자동 선택 금지 |
| 변경 | 사용자 승인만으로 시간 변경 금지, 식당 수락 후 반영, 거절·단절 시 원 시간 보존 |
| 복구·삭제 | DB·세션 재시작 복구, UNKNOWN 신규 예약 재발신 차단, 전체 삭제·세션 폐기 |
| HTTP 경계 | HttpOnly·SameSite 쿠키, Origin·Host·세션·정적 경로 검증 |

독립 HTTP 계약은 [openapi.json](openapi.json)을 참고합니다. `/api/state`는 세션의 최신 상태를 반환하고 `/api/action`은 아래 형식의 명령을 받습니다. 브라우저는 세션 쿠키와 `X-Prototype-Request: 1`을 함께 보냅니다.

```json
{
  "action": "create_trip",
  "requestId": "unique-request-id",
  "payload": {
    "conditions": {
      "partySize": 4,
      "highChairCount": 1,
      "petAccompanied": "NO",
      "stepFree": true,
      "dietaryRequirements": ""
    }
  }
}
```

같은 요청 키와 내용은 한 번만 반영합니다. 키를 다른 내용으로 재사용하면 409입니다. 전체 삭제 이후에는 이전 세션 쿠키로 명령을 재생할 수 없습니다. 일반 오류 응답은 안전한 `code`·`message`만 반환합니다.

## 실제 전화 시험
