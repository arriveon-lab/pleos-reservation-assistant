# REC-01 실제 장소 연동 검토

**후속 범위 정정:** 일반 실시간 장소 조회의 별도 미저장 시연은 [REC-04](REC04_LIVE_SEARCH.md)에서 진행합니다. #11의 예약 이력/전화 제공 조건 확정이나 #12 전체 완료가 모든 실제 조회의 선행 조건은 아닙니다. 아래 H2 snapshot에 실제 결과를 연결하지 않는 결정은 유지합니다.

확인일: 2026-11-07 KST. 담당: `tiemo0708`, GitHub [#2](https://github.com/arriveon-lab/pleos-reservation-assistant/issues/2). 구현 순서는 [REC-01 계획](REC01_PLAN.md), 실행 증거는 [STATUS](STATUS.md)를 따릅니다.

**Kakao는 목적지 주변 검색 API의 기능에 적합하지만, 현재 H2 검색 snapshot에 실제 결과를 저장하는 방식에는 연결하지 않습니다.** 공식 카카오맵 FAQ는 실시간 사용을 안내하고 별도 결과 저장을 허용하지 않는다고 설명합니다. 최근 지도/로컬 담당 답변도 원문과 파생 데이터의 기기·서버 저장을 허용하지 않는다고 안내합니다. 이 프로젝트에 대한 별도 예외가 확인된 상태는 아닙니다. [카카오맵 공식 FAQ](https://devtalk.kakao.com/t/faq-api/125610), [2026-08-20 담당 답변](https://devtalk.kakao.com/t/local-api/151263)

따라서 현재 채택 범위는 **MOCK 제품 흐름과 독립된 HTTP adapter 준비·로컬 검증**입니다. 실제 예약 흐름의 데이터 공급자로 Kakao를 최종 채택하려면 보관·재사용 범위를 해결해야 합니다. 후속 사용자 동의로 개인 오너 계정 아래 `ArriveOn` 앱을 생성하고 카카오맵을 활성화했습니다. 화면에서 일간 무료 쿼터 제공 대상과 유료 카카오맵 API의 `사용 안 함` 상태를 확인했습니다. 실제 장소 API 요청·키 값 열람/복사·비즈월렛 연결은 수행하지 않았습니다.

## 공식 근거와 프로젝트 결정

| 항목 | 확인한 내용 | 이 프로젝트의 처리 |

검색 규격은 [Kakao REST API](https://developers.kakao.com/docs/ko/kakaomap/rest-api), 활성화·무료 대상 확인은 [카카오맵 사용 방법](https://developers.kakao.com/docs/ko/kakaomap/common)을 따릅니다. [운영 정책 제5조](https://developers.kakao.com/terms/ko/site-policies)의 캐시 관련 일반 조항을 지도/로컬의 구체적인 보관 허가로 해석하지 않습니다.

[쿼터 안내](https://developers.kakao.com/docs/ko/getting-started/quota)는 카테고리 검색 무료 제공량을 일 100,000건, 유료 추가 호출 단가를 건당 2원으로 안내합니다. 제공량과 단가는 공식 문서 기준입니다. ArriveOn의 무료 대상은 확인했으며, 실제 사용 시점의 잔량과 내부 호출 상한은 별도로 확인합니다. 무료 제공량 전체를 개발 예산으로 사용하지 않고, 최초 실제 검증은 작은 호출 상한을 따로 정합니다.

## 구현한 HTTP 경계

[KakaoPlaceSearchAdapter](../server/src/main/java/ai/pleos/assistant/KakaoPlaceSearchAdapter.java)는 `PlaceSearchAdapter`를 구현하지만 Spring bean으로 등록하지 않았습니다. `WorkflowService`에는 `MockPlaceSearchAdapter`만 주입됩니다. 새 adapter는 DB·예약 상태·전화 클라이언트를 참조하지 않습니다.

| 동작 | 구현 기준 |
| --- | --- |
| 대상 | 실제 생성자는 고정 Kakao HTTPS endpoint. package-local 테스트 생성자는 명시적인 127.0.0.1 서버만 허용 |
| 요청 | GET, Authorization 헤더, FD6·목적지 x/y·반경·첫 페이지·최대 15곳. 동행자/인원/학습 동의 미전송 |
| 시간 제한 | 연결 최대 2초, 본문 수신을 포함한 요청 대기 최대 3초. timeout 시 요청 취소 |
| 취소 | 인터럽트 유지, 진행 중 future 취소, CANCELLED 반환. 호출 전 이미 취소 상태이면 전송하지 않음 |
| 응답 크기 | 수신 중 262,144 byte 초과 차단, 잘못된 UTF-8 거부. mapper의 구조·항목 검증도 적용 |
| 리다이렉트 | 따라가지 않으며 키를 다른 endpoint로 넘기지 않음 |
| 실패 | 인증·권한·429·상위 장애·잘못된 응답·timeout·취소를 내부 결과로 반환. 정상 0건과 구분 |
| 기록 | 응답 본문·키·장소 정보를 로그/DB에 쓰는 코드 없음. 실제 데이터를 test fixture로 저장하지 않음 |

애플리케이션 재시도 루프와 자동 페이지 확장은 없습니다. HTTP/1.1을 명시하고, 생성 시 아래 두 JVM 시작 옵션과 현재 속성 값이 모두 일치하는지 검사합니다. 누락·충돌·런타임에 뒤늦게 설정한 값은 생성 단계에서 차단합니다. 이 옵션은 해당 JVM의 다른 JDK HTTP Client에도 영향을 주므로 실제 통합 시 #4가 실행 프로세스 경계를 함께 결정합니다.

```text
-Djdk.httpclient.disableRetryConnect=true
-Djdk.httpclient.redirects.retrylimit=1
```

위 옵션은 최초 시도를 포함한 요청 시도 상한을 1로 두기 위한 설정입니다. `System.setProperty`로 시작 후 값을 추가하는 방식을 지원하지 않습니다. Gradle은 `:server:test` JVM에만 옵션을 전달합니다. 전역 셸·Gradle daemon·기본 MOCK 실행 설정은 바꾸지 않았으며, 옵션만으로 실제 검색 경로가 활성화되지는 않습니다. [JDK 21 공식 네트워크 속성](https://docs.oracle.com/en/java/javase/21/docs/api/java.net.http/module-summary.html), [OpenJDK 21 요청 시도 구현](https://github.com/openjdk/jdk21u/blob/master/src/java.net.http/share/classes/jdk/internal/net/http/MultiExchange.java)

[KakaoTransportStartupTest](../server/src/test/java/ai/pleos/assistant/KakaoTransportStartupTest.java)는 새 JVM을 띄워 시작 옵션 누락/잘못된 값/중복 충돌, 늦은 속성 변경과 정상 생성을 검증합니다. loopback 서버의 응답 전 단절·본문 중단·재사용 연결 단절에서도 검색당 추가 요청이 없음을 확인했습니다. 정상 빈 응답도 최초 시도가 차단되지 않고 성공합니다. 이 검증은 현재 JDK 21의 로컬 HTTP/1.1 범위이며, 실제 Kakao TLS·중간 프록시·사업자 과금 집계까지 보장한 결과는 아닙니다.

## 로컬 검증과 시범 입력

[KakaoPlaceSearchAdapterTest](../server/src/test/java/ai/pleos/assistant/KakaoPlaceSearchAdapterTest.java)는 JDK HttpServer를 127.0.0.1의 임의 포트에 띄우고 [직접 작성한 가상 응답](../server/src/test/resources/places/kakao-fictional.json)을 반환합니다. 가상 키만 사용하며 실제 Kakao 호출이나 기기 위치 수집은 없습니다. 테스트용 서버는 종료 후 정리합니다.

| 입력 | 위도 | 경도 | 목적 |
| --- | --- | --- | --- |
| 성수 입력 A | 37.544 | 127.055 | 목적지 좌표를 x/y로 전달하는 기본 사례 |
| 성수 입력 B | 37.548 | 127.047 | 다른 목적지에서도 고정 좌표로 치환하지 않음 |
| 서울숲 입력 C | 37.541 | 127.043 | 좌표 순서·반경·요청 상한 보존 |

위 값은 시범 지역 주변의 합성 테스트 입력이며, 특정 매장·주차장 위치나 실차 경로 검증 결과가 아닙니다. 실제 시범 지역 경계·범위 밖 UI·현장 데이터 품질은 #5와 결정합니다. 기본 MOCK fixture는 위치별 검색 품질을 재현하지 않습니다.

검증 범위는 요청 매핑, 정상/빈 결과, 400·401·403·429·500·503, 리다이렉트, 지연된 헤더·본문, 연결 실패, 진행 중/사전 취소, 크기·UTF-8 제한, 잘못된 키/endpoint입니다. TLS·실계정 인증·실제 쿼터·서버 IP 제한·사업자 데이터 품질은 미검증입니다.

## 서버와 화면 담당자 검토안

아래는 합의를 위한 초안이며 현재 API/DB에는 적용하지 않았습니다.

| 담당 | 검토할 결정 | 필요한 결과 |
| --- | --- | --- |
| #4 서버 | 현재 searches.payload와 commands.response_json은 후보를 영속화하므로 Kakao 원문/가공 결과와 충돌 | 저장 가능한 자체/허가 데이터로 예약을 구성하거나, 사업자에게 필요한 보관 범위를 확인 |

실시간 미리보기 구현만으로 예약 기능의 데이터 보관 문제가 해결되지는 않습니다. 공급자가 확인하지 않은 주차/아이 동반·도착 대기·예약 가능 값은 missing으로 남깁니다. 다른 공급자나 직접 확보한 장소 데이터를 검토한다면 각 출처의 보관 허용 범위를 다시 확인합니다.

## 사업자 정책 문의 등록

2026-11-07 사용자 명시 승인 후 Kakao DevTalk의 카카오맵 API(지도/로컬) 게시판에 [차량용 예약 비서의 Local API 실시간 표시와 예약 문의 연결 범위 확인](https://devtalk.kakao.com/t/local-api/152647)을 등록했습니다. 공개된 제목과 본문이 승인 문안과 일치함을 확인했습니다. 앱 이름·App ID·기능 설명과 아래 질문을 공개했으며, 키·계정 이메일·실제 연락처·첨부파일은 포함하지 않았습니다.

1. 실시간 서버 중계·일시 화면 표시와 비교 중 세션 메모리 보유의 허용 범위
2. 선택·승인한 매장의 상호·연락처를 전화/음성 공급자에 전달하는 사용
3. 예약 중복 방지·결과 대조를 위한 식별자·상호·전화번호의 이력 보관/기간/별도 승인
4. 일반 이용 범위를 벗어나는 경우 필요한 계약·공급 경로·검토 자료

현재 답변 대기 상태입니다. 문의 등록 자체를 데이터 저장·재사용·제3자 제공 허가로 취급하지 않습니다. 후속 답변은 출처·게시일과 적용 범위를 함께 확인한 뒤 설계에 반영합니다.
