## 요청/목적지 연관성과 갱신

고정 TripInfo 계약에 requestId/목적지ID/SDK 생성 시각은 없습니다. 내부 probeSessionId/revision은 앱 진단 메타데이터이며 SDK 응답의 현재 목적지를 보장하지 않습니다. 목적지 변경/취소 시 기존 값을 무효화하고 새 명시적 조회를 요구하지만 새 조회 대기 중 과거 응답을 완전히 판별할 수 없습니다. 이전 A→B 시험은 이미 완료된 Trip 뒤 변경이므로 실제 늦은 유효 응답 재현이 아닙니다.

이번 두 표본도 수동 요청입니다. 이전222.052초 무요청 구간에서 추가TripInfo0건이라는 결과를 자동 갱신 없음/주기로 바꾸지 않습니다. UTC 관측은 앱 콜백 진입 시각이며 SDK 생성/적용 시각은 미확인입니다. 제품 TTL/재연결·폴링 정책은 #1/#16/#26 합의 전입니다.

## 권한 미선언 예외

실기기 정의는 NAVI_ROUTE/NAVI_ROUTE_SEARCH 모두 normal입니다. 동일 Java 소스/별도 package에서 두 manifest 권한만 제외해 실제 SDK 초기화는 성공, 목적지 조회는 PERMISSION_DENIED(06:14:06.819745Z), 기존 값 무효화·버튼 비활성을 확인했습니다. 이 시험은 런타임 권한 거부 창/개별 권한 조합/서비스 미지원 시험이 아닙니다. 원본 앱은 보존했고 별도 시험 앱은 제거했습니다. 세부 APK hash/실행 이력은 기존 검증 문서에 있습니다.

## 남은 조건과 인수 순서

1. ETA 기준: 같은 경로의 더 긴 표본과 지원되는 실제 차량 이동/주행 재생, UI 분 표시 규칙·requestTrip의 현재 안내 경로 관계에 대한 공식 근거가 필요합니다. 현재 공개 [TripInfo 페이지](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/NaviHelper/navi-helper/ai.pleos.playground.navi.data/trip-info/entry)에서 시간 기준 설명을 확보하지 못했습니다. [Destinations](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/NaviHelper/destinations) 조회/콜백 가이드를 재확인한 것을 ETA 의미 검증으로 세지 않습니다.
2. 도착/늦은 응답: 지원되는 차량 위치/주행 재생과 지연 재현 수단이 필요합니다. 단순 Android GPS 주입의 내비 이동은 미검증이며 콜백을 합성해 통과시키지 않습니다.
3. 미지원/단절: 원본 시스템 서비스·권한을 임의로 바꾸지 않는 별도 실패 재현 환경이 필요합니다. 현재 해당 실패 재현은 미완료입니다.
4. #16/#4에서 source·검증된 변환 선행 조건·freshness 거절·요청/오류 예제를 검토하고 #26/#46과 실제/가상 표시·목적지 변경 후 이전 후보 제거를 공동 인수합니다. 기존 예약은 ETA 변경으로 자동 변경하지 않습니다. CarUx는 #25 범위입니다.

위치·이름·POI/화면/전체 로그·SDK·AVD를 공유 산출물에 넣지 않았습니다. 캡처와 원본 JSON은 Git 제외 work/captures에만 있으며 발췌 JSON에 원본 해시로 연결했습니다. 이 문서 작업은 실행 코드/SDK 의존성/서버 계약을 변경하지 않습니다.
