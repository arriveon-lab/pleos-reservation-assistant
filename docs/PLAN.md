## 목표와 전체 흐름

목적지·ETA·오늘 동행자의 필수 조건·직접 입력한 취향으로 식당 3곳을 비교하고, 결정에 필요한 누락 정보를 전화로 확인한 뒤 사용자 선택과 매장 수락을 거쳐 예약을 확정합니다.

`목적지/ETA → 동행 조건 → 후보 3곳 → 누락 정보 문의 → 후보 갱신 → 사용자 선택/예약 승인 → 매장 수락 대조 → 결과 안내`

후속으로 `지속 지연 감지 → 허용 시간/비용 대조 → 변경 요청 → 기존 예약과 변경 결과 안내`를 연결합니다. 모든 단계에서 출처·관측/적용 시각·확실성·MOCK/LIVE를 보존합니다. UNKNOWN은 성공으로 안내하거나 자동 재발신하지 않습니다.

이 문서는 개발 전체 계획입니다. 상세 계약은 [API](../api/README.md), 코드/명명 규칙은 [CONTRIBUTING](../CONTRIBUTING.md), 환경 준비는 [ANDROID_SETUP](ANDROID_SETUP.md), 현재 실행 증거는 [STATUS](STATUS.md)로 연결합니다. 참가신청 초안은 별도 비공개 Notion에 작성했으며 최종 DOCX·서명 수집·제출은 완료되지 않았습니다.

현재 병목은 Pleos 실행 환경/SDK 시간 의미 확인과 Telkit 계정·번호 준비 및 실통화 승인 확보입니다. 빌드용 Android SDK와 debug probe APK, 코드 컨벤션·영역별 에이전트 지침·Gradle 검증 명령은 준비했습니다. 서버·추천·UX 담당은 모의 계약으로 개발을 진행할 수 있습니다. 두 실연동이 확보되지 않으면 모의 시연이라고 명시하고 실제 예약 달성을 주장하지 않습니다.

차량 담당의 B단계에는 [API 선택·가용성 기준](INTEGRATIONS.md#api-선택-정책과-가용성)에 따른 지원/권한/서비스 상태 확인과 미지원 대체 흐름을 포함합니다. UX 담당의 C단계 완료 조건에는 플랫폼 주행 제한의 초기 상태·변경 반영, 상태 미확인 처리를 추가합니다. 확인되지 않은 기능은 MOCK 또는 실제 연동 성공으로 바꿔 표시하지 않습니다.

## 협업 운영과 완료 기준

- main에서 `type/<GitHub 이슈번호>-<topic>` 분기, `type(scope): 설명` 커밋/PR, 리뷰는 선택(필수 승인 0명)이며 필수 CI 3개 통과·대화 해결 후 squash merge.
- 이슈에는 담당자 1명, 입력/출력 계약, 선행 작업, 성공·실패 시나리오, 완료 조건을 기록합니다.
- 차량/전화 인터페이스 변경은 API 담당과 관련 구현 담당이 함께 검토합니다. 진척은 코드 존재와 실행 확인을 분리해 STATUS에 갱신합니다.
- 구현 완료: 관련 테스트 + 계약/문서 일치. 연동 완료: 실제 환경 로그. 제출 완료: release 설치/권한/영상/서류 검수.
- 주간 또는 통합 시점마다 차단 요소와 남은 기간을 검토합니다. 계정/비용 승인을 기다리는 작업과 로컬 진행 가능한 작업을 분리합니다.

## 필수 실패 시나리오

필수 조건 미확인/불충족, 만료된 정보, NOW/ARRIVAL 혼동, 예약 불가와 빈자리 혼동, 응답 단절, 시간/비용 불일치, 중복 명령·이벤트, 동시 예약, 변경 거절·미확인, 앱 백그라운드·재실행을 포함합니다. 서버에서 이미 검증한 항목은 STATUS를 참조하고 실제 기기/통화 증거를 추가합니다.

차량 검증에는 내비게이션 서비스 미제공, 목적지 미설정, 권한 거부, 지원하지 않는 property, 일시적 서비스 단절, 주행 UX 제한 조회 실패도 포함합니다. 각 경우의 사용자 안내·허용되는 수동 입력·자동 예약 보류를 검증하고 정상 환경 로그와 구분합니다.

## 1차 MVP와 후속 범위

1차: 한 지역·식당, 후보 최대 3곳, 명시적 동행 조건·직접 취향, 결정에 필요한 누락 정보 문의, 사용자 선택, 명시적 매장 수락. 시범 지역은 성수·서울숲 음식점으로 선택했으며, 현재 장소 fixture는 실제 지역 검색 결과가 아닙니다.

후속: 지속 ETA 지연 감지→허용 변경, 개인화 학습, 카페/체험 확대. 현재 서버의 변경 API는 정책·원 예약 보존을 검증하기 위한 모의 수동 명령입니다. 자동 ETA 변경 판단은 구현되지 않았습니다. 도입 시 5분 지연 임계·2분 지속·관측 공백 시 초기화·10분 재통화 간격을 **실험 초기값**으로 검토하고 테스트로 고정합니다. 실차 관측 전 제품 기준으로 확정하지 않습니다.

## 제출 전 필요한 결정

- 팀원 GitHub ID, 대표자, 참가 부문, 소스 라이선스. GitHub 조직은 ArriveOn Lab, 저장소는 Public으로 생성했으며 공모전 제출용 팀명은 별도 확정
- 성수·서울숲 시범 지역의 테스트 목적지·반경, Kakao 사용 조건·최종 채택, DB 경험·테스트 기기(전화 회선은 2026-11-10 Telkit으로 결정)
- 비용 승인 주체, 번호 allowlist, 최대 통화 수/분, 로그 보관·삭제 범위
- 실제/모의 구분이 드러나는 시연과 문서. 전화 예약 자체를 최초라고 주장하지 않음

차량특화성은 목적지/도착 시각과 동승자 조건의 결합으로, 기술 활용성은 실제 SDK 로그로 입증합니다. 연결 흐름의 차별화는 검증할 가설이며 이용자·사업성 수치를 임의로 만들지 않습니다.
