# PDF 기반 차량 UI 적용 검증 (2026-11-14)

Refs #68, #66, #25, #56

## 범위

사용자가 제공한 18쪽 차량 UI PDF의 3~13쪽 화면, 14~18쪽 반응형/상태/토큰/컴포넌트 구성을 대조했다. 실제 Android View에 상단 단계 표시, 넓은 창 고정 여정 요약, 독립 본문 스크롤, 하단 고정 행동, 조건 2열, 후보 카드, 승인 표, 결과 상태 배너, 변경 전후 시각 카드를 적용했다. 1100dp 미만은 요약과 단일 열로 전환한다. 긴 설명·지원하지 않는 조건은 개발 도구로 이동하되 LIVE 발신 대상·비용·120초와 시연 ETA 표시는 유지한다.

PDF의 과거 API 미연결/가상 확정 문구는 현행 계약에 맞게 구분한다. PDF의 식당·통화 대화·확정 상태를 제품에 fixture로 넣지 않았다. 실제 요청·예약·변경 결정 메서드, 인증/저장 구조와 API 계약은 변경하지 않는다. 반려동물 입력·실제 ETA·새 대화 조회 API 구현은 추가하지 않았다. 서버가 반환하지 않는 대화/예약금/조건을 생성하지 않는다.

## 검증

- Java21, format, opt-in pairedPhoneDemo/realPlaceDemo/navigationDemo verifyAll 및 계측 APK 빌드 PASS. 캐시/UP-TO-DATE 포함, NO-SOURCE를 테스트 건수로 세지 않는다.
- 기존 PAIRED_VIEW 기기 검사 PASS: MOCK 차단, UNKNOWN 유지, 변경 재확인/의사 결정, 가상 알림 서버 JSON 불변 및 완료 결과 숨김.
- PDF_VIEW: 합성 조건→후보→승인(전송하지 않음), CALLING/UNKNOWN/CONFIRMED/변경 요청/입력 제한 화면. 고정 하단 행동 버튼 전체 노출 확인, UNKNOWN 상태의 변경 승인 비활성 확인. 마지막 검사에는 DECLINED 표시도 포함했다.
- Pleos Connect v2.1.0/API34, 주간1682dp와840dp, 야간840dp에서 합성 화면 검사 PASS. 최종 보완본은 주간1682dp 재검증. 본문 스크롤과 주야간을 캡처로 대조했다. 실제 moving/전체 OEM 창/실차 검증은 아니다.
- 시험 fixture는 paired 인증을 메모리에서 제거하고 전송 없이 표시한다. 저장된 인증·예약을 삭제/초기화하지 않았으며 APK는 install -r로 업데이트했다. 기기 조회/복귀 시 기존 읽기 요청 가능, 검색·발신·변경 POST는 실행하지 않았다.
- 캡처는 Git 제외 captures/pdf-redesign/{wide,narrow,night}/. 원본 PDF/실제 사용자 정보/바이너리 APK는 Git에 추가하지 않았다.

## 검사 중 발견과 보완

최종 PAIRED_VIEW 반복에서 실제 CarUx 콜백 도착 시점 때문에 ready=false가 되어 가상 알림 검사가 한 차례 실패했다(alert not shown). 제품 제한을 완화하지 않고 화면 전용 fixture의 정차/빈 pending을 명시해 기기 상태 타이밍 의존을 제거했다. 보완 후 동일 APK의 PAIRED_VIEW 재검사 PASS. 제품 동작 변경은 없으며 실차 정차 검증으로 확대하지 않는다.

## 한계

이번 PASS는 화면·합성 상태·기존 안전 회귀다. 새 UI에서 실제 유료 추천/전화/회신을 다시 검증한 것이 아니다. 고정 ETA25분과 내일19:00 기반 예약 계산은 기존 정책을 유지한다. 미연결 기능을 시각 디자인만으로 완료로 표시하지 않는다. 사용자 후속 요청으로 #68 하위 이슈와 Draft PR로 게시한다. #66 공동 인수는 미완료이며 병합하지 않는다.
