사용자 승인으로 #13의 종료 범위를 이 시연 도구·최초 실제 검색 검증으로 정리했습니다. 추가 지역 품질·실제 IP 제한은 #18, 제품 API/화면·인증·navigation 계약은 #16으로 이관했습니다. [후속 작업과 인수 조건](REC_FOLLOWUPS.md)을 따릅니다.

## 담당 범위와 이번 목표

지역·장소 공급자 검토, 검색 query/정규화·누락/오류 처리와 실제 검색 품질 검증은 추천/장소 담당 범위입니다. 이번 도구는 최대 3곳을 확인하는 독립 개발용 시연이며 제품 차량 UI(#5), 전화·음성(#3), 인증/운영 DB(#4)의 완료를 대신하지 않습니다.

사용자가 실제 검색 검증 진행을 지시했습니다. 이번 최초 실제 실행 범위는 아래 **1회**입니다. 비용 발생이 확인되면 실행 전에 중단하며 전화·예약·유료 AI 호출은 포함하지 않습니다.

| 항목 | 최초 검증 범위 |

## 문의 답변과 진행 조건의 구분

일반적인 실시간 Local API 검색은 별도 DevTalk 답변을 필수 조건으로 하는 기능이 아닙니다. [공식 사용 절차](https://developers.kakao.com/docs/ko/kakaomap/common)는 앱 생성·카카오맵 활성화·REST 키 설정을 안내하고, [공식 FAQ](https://devtalk.kakao.com/t/faq-api/125610)는 실시간 호출과 별도 결과 저장 금지를 설명합니다.

따라서 저장 검색/예약 흐름과 독립된 이 시연은 #11 전체 문의 답변이나 #12 전체 완료를 기다리지 않습니다. 현재 H2 `searches.payload`·`commands.response_json`에는 실제 결과를 연결하지 않습니다. 예약 이력 보관·비교 세션의 보유 범위·전화/음성 공급자 전달은 #11의 별도 사용 조건 검토 대상입니다. 일반 공유 예외를 로컬 저장 허가로 해석하지 않습니다.

## 구현한 실행 경계

[PlacePreviewDemo](../server/src/main/java/ai/pleos/assistant/PlacePreviewDemo.java)는 Spring/Store/DB를 시작하지 않는 별도 main입니다. 개발용 loopback HTML 도구이며 서비스 `/api/v1`·공개 DTO/OpenAPI 계약을 변경하지 않습니다. 제품 서버의 기본 MOCK과 LIVE 시작 차단은 유지합니다.

- 기본은 MOCK. `placePreviewMode=live`를 명시해야만 기존 Kakao HTTP adapter를 생성합니다. 이 옵션은 제품 `app.mode=LIVE`와 별개입니다.
- 127.0.0.1의 임의 포트/임의 경로에만 바인딩합니다. 정확한 주소의 첫 GET에서만 조회하며, 다른 경로/query·POST·cross-site·prefetch는 조회 전에 거부합니다.
- 정상 0건과 실패를 구분하고, 기대한 출처와 다른 데이터나 3곳 초과 응답은 표시하지 않습니다. 사용자 조건/예약 사실을 생성하지 않습니다.
- 동시 열기·새로고침으로 추가 조회하지 않습니다. 응답을 보낸 뒤 프로세스를 종료하고 원문/HTML 캐시를 남기지 않습니다. 브라우저 표시는 5분 뒤 지웁니다.
- no-store·no-referrer·CSP 적용, 외부 리소스/분석 도구 없음. 상호/주소 문자열은 HTML escape합니다. 실제 결과 화면 캡처나 원문을 Git 산출물로 남기지 않습니다.
- HTTP/1.1, JDK 연결 재시도 비활성화·요청 시도 상한 1의 시작 옵션을 적용합니다. JDK HTTP traffic logging은 비활성화합니다. 실제 네트워크/사업자 집계는 실행 결과와 함께 확인합니다.
- 안전한 실행 상태·표시 개수·불량 제외 수만 stdout에 요약합니다. 키·상호·ID·주소·연락처·응답 본문은 출력하지 않습니다.

## 실행 방법과 키

기본 가상 화면:

```bash
./gradlew -PincludeAndroid=false :server:placePreview
```

실제 검색은 무료 적용/잔량과 유료 꺼짐을 확인한 뒤 실행합니다. 아래 명령은 `PREVIEW_URL`을 출력하며, 그 주소를 브라우저 주소창에서 직접 한 번 엽니다. 첫 표시 후 새로고침은 추가 검색을 하지 않으며, 재실행은 별도 조회입니다.

```bash
./gradlew -PincludeAndroid=false :server:placePreview \
  -PplacePreviewMode=live \
  -PplacePreviewKeyFile=work/secrets/kakao-rest-api-key
```

키는 채팅·Git·APK·명령행 값에 넣지 않습니다. `work/`는 Git 제외이며 키 파일은 소유자 전용 `0600`, 부모 디렉터리는 `0700`으로 준비합니다. 도구는 symlink·타인에게 열린 권한·빈/과도한 크기의 키 파일을 거부합니다. 키 파일을 지정하지 않은 실제 모드에서는 `KAKAO_REST_API_KEY` 환경변수를 읽습니다. `.env` 자동 로딩은 없습니다. 파일 권한 검증 경로는 macOS/Linux 기준이며 Windows에서는 환경변수 방식도 별도 실행 검증 전입니다.

현재 ArriveOn의 기존 REST 키를 사용자 지시에 따른 로컬 설정으로 안전하게 준비했습니다. 새 키 발급·재발급·권한/IP 제한 변경은 하지 않았고 값은 출력하지 않았습니다. 앞선 문서의 ‘키 값 복사 없음’은 이 설정 이전의 기록입니다.

## 가상 검증과 최초 실제 실행 기록

- [PlacePreviewDemoTest](../server/src/test/java/ai/pleos/assistant/PlacePreviewDemoTest.java) 12개: 1회 표시/재조회 방지, 잘못된 요청 6종, 동시 열기, 실패 구분, HTML escape/비표시 필드, 출처/개수 검증, 키 권한/symlink 거부.
- main 기준 기존 144개 + 신규 12개 = **156개 실행, 실패/오류/skip 0**. `format verify`와 패키징 JAR MOCK HTTP/OpenAPI/H2 재시작/LIVE 시작 차단 통과.
- 위 156개와 PR #14의 188개는 병합 전 서로 다른 브랜치의 기록입니다. PR #14가 통합된 main `8cbe890`과 함께 서버 **200개 실행, 실패/오류/skip 0**, `verifyAll`과 JAR smoke/계약 검증을 통과했습니다. Android 단위 테스트는 NO-SOURCE이고 기기 실행은 검증하지 않았습니다. [STATUS](STATUS.md)에 통합 결과를 기록했습니다.
- 최초 실제 실행: **성공**. Kakao 실제 요청 1회, 최대 3곳 중 3곳 표시, 불량 제외 0. 브라우저에서 실제 출처·미확인 조건 표시를 확인했고 응답 원문/식별자/주소/연락처/결과 캡처는 저장하지 않았습니다.
- 공급자 콘솔의 카테고리 검색 사용량이 실행 전 호출 없음에서 **1 / 100,000**으로 바뀐 것을 확인했습니다. 유료 API는 사용 안 함, 실제 비용 0원, 전화/예약/AI 호출 0회입니다. TLS/키 인증과 실제 쿼터 1회 집계를 확인한 결과이며 전체 장애/사업자 품질을 검증한 것은 아닙니다.
- 기존 REST 키의 호출 허용 IP 목록은 비어 있었고 설정을 변경하지 않았습니다. IP allowlist 거절 사례와 나머지 합성 목적지는 아직 미검증입니다. 실행 메타데이터만 Git 제외 `work/rec04-first-live-result.json`에 기록했습니다.

## 남은 작업

1. 최초 1회에서 TLS·인증·쿼터 집계·실시간 표시를 확인했습니다. 실제 결과 원문/캡처를 저장하지 않는 경계를 유지하고 나머지 품질 검증 범위를 정합니다.
2. 나머지 시범 입력·빈/불량·지역 데이터 품질은 별도 호출 범위와 근거를 잡아 검증합니다. 1회 성공을 전체 지역 품질 검증 완료로 세지 않습니다.
3. #16에서 #5에 결과/빈 결과/실패·출처/예약 모드 구분을 전달하고, #4와 제품 API/인증/화면 계약을 확정합니다.
4. GPT 보완 검색은 사용 가능한 출처·최신 시각·미확인 사실을 구분하며, 실제 유료 호출은 별도 승인 전 실행하지 않습니다. 전화 공급자/예약 이력의 데이터 범위는 #11/#3에서 별도로 확인합니다.

#13은 최초 실행·독립 시연 검증만 PR #15의 종료 범위로 정리했습니다. 위 추가 품질 검증은 #18, 제품 연결은 #16, 데이터 사용 조건은 #11에서 계속 진행합니다. 이번 병합은 지역 전체 품질·실예약·제품 통합 완료를 뜻하지 않으며 실제 호출을 추가하지 않습니다.
