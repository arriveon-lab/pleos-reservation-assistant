Kakao 근거와 기존 문의를 재확인하고 OA-18655/공공누리 조건을 추가했습니다. 기존 Naver/Google 비교는 2026-11-08 확인 이력입니다. 프로젝트에 대한 별도 허가나 팀 최종 공급자 합의를 받은 문서가 아닙니다. 최신 개발 결정과 검증 순서는 [MVP 데이터 흐름](REC02_MVP_DATA_FLOW.md)을 우선합니다.

## 우리 문의의 최신 공개 확인

[기존 승인 문의](https://devtalk.kakao.com/t/local-api/152647)를 2026-11-09에 공개 열람하고 공개 JSON 메타데이터를 대조했습니다. posts_count=1, reply_count=0, 보이는 글 번호1이며 운영자 추가 답변은 확인되지 않았습니다. 공개 글 수정·재문의·메시지 발송은 없습니다. 이후 답변은 작성자·날짜·대상 기능을 다시 대조한 뒤 반영합니다. 비밀 없는 [확인 근거](policy/rec02-evidence-2026-11-09.json)를 함께 제공합니다.

문의의 남은 답변 범위는 실시간 중계와 비교 중 메모리 보유의 차이, 선택 장소의 전화/음성 공급자 전달, 중복 방지/대조를 위한 예약 이력 필드·기간, 별도 계약 또는 공급 경로입니다.

## 개발 경계 결정

현재 제품은 MOCK, Kakao는 독립 미저장 검색 검증으로 한정합니다. 실제 장소에 MOCK 문의/예약 facts를 붙이거나 실제 예약이 된 것처럼 표시하지 않습니다. 다음 검증은 OA-18655를 우선하고 직접 제공 매장 경로를 병행 후보로 두며, 실제 예약 공급자는 품질/권한·팀 인수 후 확정합니다. 핵심 예약 기능을 임의로 제외하거나 담당을 변경하지 않습니다. 구체적 DATA-01–08과 단계별 입력/출력은 [MVP 데이터 흐름](REC02_MVP_DATA_FLOW.md)을 따릅니다.

전화 흐름을 병행 개발할 때는 가상 fixture 또는 필요한 이용 권한을 별도로 확보한 매장 정보를 사용하도록 계약을 분리합니다. Kakao 결과를 사용자가 재입력/확인했다는 이유만으로 직접 확보한 데이터로 provenance를 바꾸지 않습니다.

## 직접 확보 데이터의 검토용 provenance 계약

아래는 #3/#4/#5에 인계할 설계이며 공개 API·DB 스키마에 적용하지 않았습니다.

| 항목 | 확인할 내용 |
| --- | --- |
| sourceKind·sourceEvidenceRef | 실제 제공 출처와 권한 증빙의 내부 참조. 다른 사업자 결과를 직접 확보로 재분류하지 않음 |
| allowedPurposes | 표시·전화 문의·음성 처리 업체 제공·예약 이력 보관을 각각 명시 |
| permittedFields | 상호/주소/연락처/매장 식별자별 사용 범위. 불필요한 필드 수집 없음 |
| validFrom·validUntil | 사용/재사용 가능한 기간, 재확인 조건 |
| retentionPolicy·withdrawal | 보관 기간·삭제/철회·기존 예약 대조 시 처리 |
| processorScope | 전달할 업체·필드·목적·보존/삭제 조건과 필요한 계약 |

실제 연락처·증빙 원문·서명·사용자 동의서는 공개 Git에 넣지 않습니다. 이력/전화 기능의 입력은 권한 증빙과 사용자 발신 승인·비용 상한을 모두 충족해야 합니다. 데이터 사용 허가와 실제 전화 실행 승인은 별개입니다.
