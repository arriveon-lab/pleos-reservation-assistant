# REC-02 장소 데이터 이용 범위와 공급 경로

## 2026-11-10 공모전 MVP — 검색 기반 추천과 직접 피드백

사용자는 매장/리뷰를 자체 DB에 수집하기보다 **요청 시 웹검색으로 조건별 근거를 취합해 추천하고, 사용자 요청·선택·직접 평가를 저장**하는 방향으로 진행을 지시했습니다. [#50](https://github.com/arriveon-lab/pleos-reservation-assistant/issues/50)에서 조건 추천·MOCK 실험 API·사용자 데이터 저장을 구현합니다. 기존 #48/#49 공공 catalog는 매장 식별/연락처 확보의 선택적 기반이며 웹검색 추천의 필수 선행 조건이 아닙니다.

- 정식 웹검색 도구를 통한 요청별 검색/인용과 네이버 등 특정 플랫폼을 직접 크롤링해 DB로 쌓는 방식을 구분합니다. 모든 매장과 개별 제휴/허가를 받아야만 추천 개발을 시작하는 절차는 두지 않습니다. 실제 통합에는 검색 서비스와 원 출처의 조건을 유지하며 공모전이라는 이유로 일괄 면제하지 않습니다.
- 웹 판정 YES/NO/UNKNOWN/CONFLICT는 세션의 보고이며 독립 검증·예약 가능·발신 승인이 아닙니다. 리뷰만 있는 조건은 UNKNOWN, 명시적 상충은 CONFLICT로 보존하고 실내 애견 여부는 일반 애견동반과 분리합니다.
- DB에는 사용자 구조화 요청·선택 ordinal·직접 평가 MATCH/PARTIAL/NO_MATCH와 이유만 저장합니다. 웹 원문/리뷰/상호/주소/전화/URL/AI 판정/응답 snapshot은 저장하지 않습니다. O로 줄인다고 출처 제한이 없어지는 예외를 만들지 않습니다. 장기 매장 사실 저장은 출처별 허용 범위를 따릅니다.
- personalizationConsent는 후속 개인화 대상 구분이며 현재 모델 학습은 없습니다. 사용자 직접 선택/평가는 매장 검증이나 예약 권한으로 바꾸지 않습니다.

[OpenAI 공식 웹검색 안내](https://developers.openai.com/api/docs/guides/tools-web-search)는 검색·출처 인용 기능을 설명하며, 그 기능 자체가 모든 출처의 저장/재제공 권한을 보장하는 것으로 해석하지 않습니다. 이 문서 갱신은 실제 모델/웹 수집/전화/유료 호출0회, #11 OPEN/#23 Draft입니다. 아래 공공데이터 우선 결정은 예약용 독립 정보 경로의 이력으로 유지합니다.

### 저장·전달 계약

- `sourceKind=SEOUL_OPEN_DATA`, dataset ID·원천 관리번호·자체 ID·원본 URL·라이선스·출처표시·취득 시각·원본 수정시각 문자열과 시간대 미확인을 함께 보존합니다. 취득/검색 시각으로 원본 시각을 덮지 않습니다. 실제 원문/연락처는 Git에 넣지 않습니다.
- 인허가상 정상·전화 형식 통과는 현재 영업/예약 가능/번호 확인/발신 승인이 아닙니다. 후보 최대3개와 기존 UNKNOWN 질문을 유지합니다. 누락 번호·모바일 검토·범위 밖·중복/상태 충돌은 안전하게 제외/차단합니다.
- DB의 후보/예약 스냅샷은 필드별 실제 출처를 보존해야 합니다. 전화 담당에게는 별도 확인된 매장 연락처와 사용자 승인·비용/횟수 상한만 전달하며 Kakao 후보 ordinal/ID를 발신 대상으로 바꾸지 않습니다. processor/보관/삭제 인수 전 `inquiryDispatchAllowed=false`입니다.
- 이번 #48은 로컬 오프라인 catalog·검색 adapter·가상 검증입니다. 운영 DB migration·공개 미리보기 필드·앱 채택은 #4/#16/#26과 별도 합의합니다. 기본 MOCK/LIVE 차단은 유지합니다.

## 우리 문의의 최신 공개 확인

[기존 승인 문의](https://devtalk.kakao.com/t/local-api/152647)를 2026-11-09에 공개 열람하고 공개 JSON 메타데이터를 대조했습니다. posts_count=1, reply_count=0, 보이는 글 번호1이며 운영자 추가 답변은 확인되지 않았습니다. 공개 글 수정·재문의·메시지 발송은 없습니다. 이후 답변은 작성자·날짜·대상 기능을 다시 대조한 뒤 반영합니다. 비밀 없는 [확인 근거](policy/rec02-evidence-2026-11-09.json)를 함께 제공합니다.

문의의 남은 답변 범위는 실시간 중계와 비교 중 메모리 보유의 차이, 선택 장소의 전화/음성 공급자 전달, 중복 방지/대조를 위한 예약 이력 필드·기간, 별도 계약 또는 공급 경로입니다.

추가 근거: [성동구 OA-18655](https://data.seoul.go.kr/dataList/OA-18655/A/1/datasetView.do), [공공누리 제1유형](https://www.kogl.or.kr/info/licenseType1.do). 재사용 조건과 전화 발신·개인정보·업체 처리 조건을 분리하고, 카탈로그의 갱신주기를 실제 최신성 보장으로 해석하지 않습니다.

## 개발 경계 결정

현재 제품은 MOCK, Kakao는 독립 미저장 검색 검증으로 한정합니다. 실제 장소에 MOCK 문의/예약 facts를 붙이거나 실제 예약이 된 것처럼 표시하지 않습니다. 다음 검증은 OA-18655를 우선하고 직접 제공 매장 경로를 병행 후보로 두며, 실제 예약 공급자는 품질/권한·팀 인수 후 확정합니다. 핵심 예약 기능을 임의로 제외하거나 담당을 변경하지 않습니다. 구체적 DATA-01–08과 단계별 입력/출력은 [MVP 데이터 흐름](REC02_MVP_DATA_FLOW.md)을 따릅니다.

전화 흐름을 병행 개발할 때는 가상 fixture 또는 필요한 이용 권한을 별도로 확보한 매장 정보를 사용하도록 계약을 분리합니다. Kakao 결과를 사용자가 재입력/확인했다는 이유만으로 직접 확보한 데이터로 provenance를 바꾸지 않습니다.

## 직접 확보 데이터의 검토용 provenance 계약

아래는 #3/#4/#5에 인계할 설계이며 공개 API·DB 스키마에 적용하지 않았습니다.

| 항목 | 확인할 내용 |
| --- | --- |
| sourceKind·sourceEvidenceRef | 실제 제공 출처와 권한 증빙의 내부 참조. 다른 사업자 결과를 직접 확보로 재분류하지 않음 |
| allowedPurposes | 표시·전화 문의·음성 처리 업체 제공·예약 이력 보관을 각각 명시 |
| permittedFields | 상호/주소/연락처/매장 식별자별 사용 범위. 불필요한 필드 수집 없음 |
| validFrom·validUntil | 사용/재사용 가능한 기간, 재확인 조건 |
| retentionPolicy·withdrawal | 보관 기간·삭제/철회·기존 예약 대조 시 처리 |
| processorScope | 전달할 업체·필드·목적·보존/삭제 조건과 필요한 계약 |

실제 연락처·증빙 원문·서명·사용자 동의서는 공개 Git에 넣지 않습니다. 이력/전화 기능의 입력은 권한 증빙과 사용자 발신 승인·비용 상한을 모두 충족해야 합니다. 데이터 사용 허가와 실제 전화 실행 승인은 별개입니다.
