# REC-02 장소 데이터 이용 범위와 공급 경로

확인일: 2026-11-08 KST. 담당 `tiemo0708`, [#11](https://github.com/arriveon-lab/pleos-reservation-assistant/issues/11). 공식 공개 문서를 읽어 현재 개발 경계와 확인할 사항을 정리했습니다. 프로젝트에 대한 별도 허가나 팀 최종 공급자 합의를 받은 문서가 아닙니다.

## 현재 확인한 경계

| 사용 목적 | 확인 근거 / 상태 | 현재 프로젝트 적용 |
| --- | --- | --- |

| 결과/가공 데이터의 기기·서버 DB/캐시 | FAQ와 지도/로컬 담당 답변은 별도 저장 사용을 허용하지 않는다고 안내 | 실제 응답을 places·searches.payload·commands snapshot에 넣지 않음 |

## 우리 문의의 최신 공개 확인

[기존 승인 문의](https://devtalk.kakao.com/t/local-api/152647)를 2026-11-08에 공개 열람했습니다. 열람본에는 작성자 글만 확인되고 운영자 답변은 확인되지 않았습니다. 공개 글을 수정하거나 재문의·메시지를 발송하지 않았습니다. 캐시/페이지 표시 지연 가능성이 있으므로 담당 답변은 작성자·날짜·대상 기능을 다시 대조한 뒤 반영해야 합니다.

문의의 남은 답변 범위는 실시간 중계와 비교 중 메모리 보유의 차이, 선택 장소의 전화/음성 공급자 전달, 중복 방지/대조를 위한 예약 이력 필드·기간, 별도 계약 또는 공급 경로입니다.

## 공급 경로 비교

| 경로 | 확인한 기능/제약 | 현재 판단 |

| Naver 지역 검색 | 검색어 중심, 표시 최대5/시작1, 정확도 또는 리뷰 수 정렬. telephone은 값을 주지 않는 호환용 필드 | 좌표/반경·연락처 요구의 직접 대체로 단정하지 않음. 별도 이용 조건 확인 필요 |
| Google Places | 보관 제한과 place ID 예외, 지도/지도 없는 표시의 출처 표기 조건 등 존재 | API 교체만으로 저장/전화 전달 문제가 해결된다고 보지 않음. 지도 호환·필드·요금/약관 검토 전 채택/실행 없음 |
| 직접 이용 권한을 확보한 매장 데이터 | 필드·표시·전화 제공·이력 보관·기간을 제공자와 직접 정할 수 있는 후보 | #3/#4와 검토할 별도 공급 경로. 실제 권한 확보/매장 계약/발신은 아직 없음 |

비교 근거: [Kakao REST](https://developers.kakao.com/docs/ko/kakaomap/rest-api), [Naver 지역 검색](https://developers.naver.com/docs/serviceapi/search/local/local.md), [Google Places 정책](https://developers.google.com/maps/documentation/places/web-service/policies). Naver 필드에 연락처가 없다는 점과 Google place ID 예외를 서로 다른 공급자의 일반적인 보관 허가로 확대하지 않습니다. 계정·유료 설정·API 호출은 수행하지 않았습니다.

## 개발 경계 결정

현재 제품은 MOCK, Kakao는 독립 미저장 검색 검증으로 한정합니다. 실제 장소에 MOCK 문의/예약 facts를 붙이거나 실제 예약이 된 것처럼 표시하지 않습니다. 실제 예약 공급 경로는 아직 최종 확정하지 않습니다. 팀의 핵심 기능을 임의로 제외하거나 다른 담당자의 범위를 변경하지 않았습니다.

전화 흐름을 병행 개발할 때는 가상 fixture 또는 필요한 이용 권한을 별도로 확보한 매장 정보를 사용하도록 계약을 분리합니다. Kakao 결과를 사용자가 재입력/확인했다는 이유만으로 직접 확보한 데이터로 provenance를 바꾸지 않습니다.

## 직접 확보 데이터의 검토용 provenance 계약

아래는 #3/#4/#5에 인계할 설계이며 공개 API·DB 스키마에 적용하지 않았습니다.

| 항목 | 확인할 내용 |
| --- | --- |
| sourceKind·sourceEvidenceRef | 실제 제공 출처와 권한 증빙의 내부 참조. 다른 사업자 결과를 직접 확보로 재분류하지 않음 |
| allowedPurposes | 표시·전화 문의·음성 처리 업체 제공·예약 이력 보관을 각각 명시 |
| permittedFields | 상호/주소/연락처/매장 식별자별 사용 범위. 불필요한 필드 수집 없음 |
| validFrom·validUntil | 사용/재사용 가능한 기간, 재확인 조건 |
| retentionPolicy·withdrawal | 보관 기간·삭제/철회·기존 예약 대조 시 처리 |
| processorScope | 전달할 업체·필드·목적·보존/삭제 조건과 필요한 계약 |

실제 연락처·증빙 원문·서명·사용자 동의서는 공개 Git에 넣지 않습니다. 이력/전화 기능의 입력은 권한 증빙과 사용자 발신 승인·비용 상한을 모두 충족해야 합니다. 데이터 사용 허가와 실제 전화 실행 승인은 별개입니다.
