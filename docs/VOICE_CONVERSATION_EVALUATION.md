# 한국어 예약 대화 평가

2026-11-14 기준. 실제 식당 역할을 하는 사용자의 시험 통화 피드백에서 평가 항목을 정했다.

## 참고한 공식 자료

- LiveKit은 음성 답변을 짧게 하고 한 번에 한 가지를 질문하도록 안내한다. 여러 정보를 받은 뒤에는 남은 항목만 질문하도록 현재 프롬프트를 보강했다. [Prompting guide](https://docs.livekit.io/agents/start/prompting/)
- `AgentSession.run`으로 실제 모델의 응답과 도구 호출을 평가할 수 있다. `mock_tools`는 실제 도구 스키마를 유지하면서 실행을 대체한다. 모델을 사용하는 이 평가는 추론 요금이 발생하며, 아래 로컬 재현 검사와 별도로 실행해야 한다. [Unit tests](https://docs.livekit.io/testing/unit-tests/)
- 시나리오는 발화자의 목적, 시작 발화, 제공할 사실, 기대 결과를 명시하고 한 사례에 하나의 어려움을 넣는다. 아래 사례는 실제 모델 평가에도 사용할 수 있는 기준이며 모델 평가 실행 결과는 아직 없다. [Write a scenario](https://docs.livekit.io/testing/simulations/write-a-scenario/)

## 로컬에서 재현한 문제와 수정

비용을 묻는 질문에 식당이 “추가 비용은 없어요. 유아의자도 있습니다.”라고 답하면 기존 코드는 전체 답이 짧은 비용 답변 정규식과 맞지 않아 재질문했다. 같은 형태로 다시 답하면 조기 보류할 수 있었다.

명확한 비용 답변 문장이 다른 정보와 함께 있으면 전체 발화를 다음 대화 처리에 전달한다. 물음표는 유지하므로 “추가 비용은 없어요?”와 잘못 전사된 “추가 배움 없습니다”는 재확인 대상이다. 이 처리는 예약 확정이나 시설 조건 충족을 자동 저장하지 않는다. 관련 회귀 테스트는 원래 발화 전체가 보존되고 예약이 CALLING으로 유지되는지도 검사한다.

프롬프트에는 여러 항목의 동시 답변, 긍정·부정이 섞인 답변, 시간 정정, 짧은 수락을 문맥에 맞게 처리하는 지침을 추가했다. 실제 모델이 새 지침을 따르는지는 미검증이다.

## 대화별 평가 기준

| 상황 | 식당의 발화 예시 | 기대 결과 | 현재 검증 |
| --- | --- | --- | --- |
| 여러 정보 동시 제공 | 추가 비용은 없어요. 유아의자도 있습니다. | 비용 재질문 없이 전체 발화를 다음 단계에 전달 | 실제 worker hook 가상 입력 통과 |
| 물음과 오인식 | 추가 비용은 없어요? / 추가 배움 없습니다. | 불확실한 비용만 재확인 | 로컬 테스트 통과 |
| 짧은 수락 | 이름으로 예약 부탁 후 “네” | 해당 요청의 수락으로 판정 | 로컬 테스트 통과 |
| 가능 여부 답변 | 예약 가능할까요에 “네” | 가능 여부만 확인, 최종 예약 수락 별도 확인 | 로컬 테스트 통과 |
| 대기와 정정 | 잠시만요 / 잠시만요, 일곱 시 말고 여덟 시요 | 순수 대기는 기다리고 정정은 대화 처리에 전달 | 로컬 테스트 통과 |
| 필수 조건 불가 | 주차는 되는데 유아의자는 없어요 | 각 항목을 구분하고 필수 조건 불가면 예약 보류 | 모델 해석 미검증 |
| 사용자 승인 | 예약을 저녁 일곱 시 반으로 미뤄 주세요 | 사용자 결정 대기, 수락 후 식당 재확인으로 변경 | 도구·상태 테스트 통과, 자유 대화 미검증 |
| 답변 반복 | 앞서 시간과 인원을 이미 답함 | 새 정보가 없으면 같은 질문을 반복하지 않음 | 프롬프트 보강, 모델 평가 미실행 |

실제 모델 평가는 가상 이름·조건과 메모리 DB를 사용하고, 생성된 대화와 도구 인자 및 최종 상태를 함께 확인해야 한다. 자연스러운 표현은 의미 평가로, 시간·비용·승인 여부는 코드의 상태 검증으로 판정한다. 단순 문구 일치만으로 대화 자연스러움을 통과 처리하지 않는다.

## 재실행

음성 SDK가 설치된 가상환경에서 저장소 루트 기준으로 실행한다. `PHONE_ENV_FILE`은 존재하지 않는 경로로 지정해 실전화 설정 자동 로딩을 피한다.

```bash
PHONE_ENV_FILE=/tmp/arriveon-offline-missing.env python -m unittest \
  prototypes.phone_agent.voice.test_voice \
  prototypes.phone_agent.voice.test_resilience \
  prototypes.phone_agent.voice.test_echo \
  prototypes.phone_agent.voice.test_agent_text \
  prototypes.phone_agent.test_paired_phone -v
```

로컬 138개 테스트 통과. 신규 테스트 2개에 복합 답변 3종과 질문·오인식 3종을 포함했다. 언어 모델 호출·실전화·오디오 청취·EC2 배포는 이번 실행에 포함되지 않았다.

## 실제 모델 후속 평가

2026-11-14 사용자 승인 후 Gemma 4 31B로 준비된 대화 이력에 대한 다음 응답 6개를 평가했다. 복합 답변 후 이름으로 예약 요청, 짧은 수락의 확정, 비용 재확인을 확인했다. 한 번에 두 조건 질문, 승인되지 않은 대체 시간 질문, 조건 불가 안내 뒤 종료 도구 미호출은 남았다. 첫 실행의 입력 hook 누락을 수정하고 영향받은 두 사례를 재검증했다. 전체 통화·음성 평가와 반복 성공률 검증은 미실행이다.

`python -m prototypes.phone_agent.voice.conversation_eval --output /tmp/conversation-offline.json`은 가짜 모델로 SDK 실행 경로를 확인한다. `--run-model --env-file /비공개/설정.env`를 추가하면 실제 유료 추론을 수행한다. `--scenario`로 개별 사례를 선택할 수 있다. 실제 모델은 현재 코드의 기본 모델 또는 해당 설정의 PHONE_LLM_MODEL을 사용한다. 결과의 REQUIRES_REVIEW는 생성 완료를 뜻하며 대화 품질 통과를 뜻하지 않는다.

## 수정 후 문제 사례 3개 재검증

2026-11-14 추가 승인 후 같은 모델로 세 사례를 다시 평가했다.

- 가능 여부 답변 후 “유아의자 한 개 이용할 수 있을까요?” 한 항목만 질문했다.
- 다른 시간만 가능하다는 답에는 finish_call을 호출하고 보류 안내 후 agent_finished로 종료했다. 예약 상태는 UNKNOWN이며 20시 예약을 요청하지 않았다.
- 필수 유아의자 불가에도 finish_call을 호출해 보류 안내와 종료를 마쳤다. CALLING에 남아 있지 않았다.

예약이 성사되지 않았고 확정 근거가 없으므로 종료 후 UNKNOWN을 유지하는 기존 정책을 사용했다. 서버가 확실한 예약 거절로 분류하는 DECLINED까지 확인한 결과는 아니다.

프롬프트에 새 예약 행동 순서와 짧은 사례를 넣고, finish_call 종료 후 StopResponse로 추가 모델 발화를 중단했다. 기존 상대 응답 대기 차단은 유지한다. 로컬 139개 검사 통과. 세 사례 각 1회 관측이며 반복 성공률과 실제 음질은 미검증이다. 수정본은 로컬이며 EC2 배포·GitHub 게시·실전화는 수행하지 않았다. 추가 모델 사용료 예상은 승인받은 US$0.005~0.03, 실제 청구액은 미대조다.
