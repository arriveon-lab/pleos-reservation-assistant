# INT-01 차량 추천·전화 AI 통합 계획

담당: #52. 이 문서는 구현 순서와 담당 간 계약 초안이다. 미병합 Draft PR의 코드를 main 기능으로 간주하지 않는다.

## 사용자 흐름

1. Gleo가 `목적지 근처 맛집 추천해줘`를 앱 기능으로 전달한다. 주차는 기본 필수 조사 조건이고, 아기의자·계단이 적은 접근 동선 등은 별도 조건이다.
2. 앱은 Pleos 목적지와 관측 시각·경로 세대를 추천 서버에 전달한다. 서버는 작업 ID를 반환한다. Gleo에는 즉시 접수 응답을 보낸다.
3. 서버는 Kakao로 실제 후보를 찾고 GPT 웹검색으로 리뷰와 조건 근거를 조사한다. 필수 조건이 UNKNOWN/CONFLICT이면 전화 AI에 확인을 요청한다.
4. 서버는 전화 답변의 출처·확실성·시각을 보존해 최대 3곳을 선정한다. 앱은 작업을 폴링하고 완료 결과를 화면에 표시하고 Pleos TTS로 읽는다.
5. 사용자가 후보를 선택해 예약을 승인하면 최신 Pleos 도착 예정 시각과 인원을 전화 AI에 전달한다. 명시 수락·시각·비용 일치 전에는 확정으로 표시하지 않는다.
6. 예약 후 앱이 약 10분마다 Pleos ETA를 관측한다. 검증된 도착 시각이 확정 예약 시각보다 10분 이상 늦으면 사용자에게 지연 연락 여부를 묻는다. 사용자가 그 시점에 승인한 경우에만 서버가 동일 지연 중복 발신을 막고 전화 AI에 지연 통보를 요청한다. 통보 완료와 매장의 예약 시각 변경 수락은 별도 상태다.

## 재사용과 신규 작업

현재 목표는 내비 **목적지 주변** 추천이다. 현재 위치·차량 속도 조회와 식당별 우회시간 계산은 이 기능의 입력에 포함하지 않는다. 예약·지연 안내에 필요한 Pleos ETA는 시간 기준과 현재 경로 연관성을 검증한 뒤 사용한다.

| 영역 | 재사용 | 새로 구현할 것 |
| --- | --- | --- |
| 차량 | #1/PR #47 NaviHelper probe | 제품 앱의 SDK 비의존 목적지/ETA adapter, 경로 세대·신선도·무효화, 기기 검증 |
| 화면·음성 | #26/PR #36 인증·미리보기 화면 | Gleo App Schema/action, 즉시 접수, 작업 폴링, 완료 TTS, 후보 선택·예약 승인 |
| 장소·추천 | KakaoPlaceSearchAdapter, #16/PR #19, #50/PR #51 웹검색 판정 | 실제 후보→조건 조사→전화 확인→최종 순위 연결, 비동기 상태/결과 계약 |

## 전화 AI 담당자와 합의할 계약

현재 프로토타입의 `/api/state`, `/api/action`, `/api/live/dial`은 이 제품 계약을 확정하지 않는다. #43 담당과 아래 세 작업을 독립된 타입으로 합의한다.

| 작업 | 필수 요청 | 필수 결과 |
| --- | --- | --- |
| 조건 문의 | 작업 ID, 후보 식별자/지점, 허용된 연락처, 질문 키·문구, 승인/실행 모드, 멱등 키 | 질문별 YES/NO/UNKNOWN, 매장 발화 근거, 관측 시각, 통화 상태·비용 |
| 예약 | 선택 후보, 인원, 요청 시각·시간대, 필수 조건, 사용자 승인 참조, 비용 상한, 멱등 키 | ACCEPTED/REJECTED/UNKNOWN, 매장 수락 시각·인원·비용, 근거·통화 ID |
| 지연 통보 | 기존 예약 참조, 기존 확정 시각, 새 예상 시각, 통보할 지연, 사용자 권한, 멱등 키 | 전달 여부, 매장 응답, 변경 수락 여부·새 확정 시각·비용, UNKNOWN |

세 작업 모두 비동기 작업 ID/상태 조회, 취소 가능 범위, 콜백 인증 또는 폴링, timeout, 중복 이벤트 처리, 통화 횟수·비용 상한을 정해야 한다. 단순 전달 성공을 예약 변경으로 해석하지 않는다.

## 구현 순서와 확인 기준

1. PR #47/#36/#19/#51/#45의 최신 계약과 소유 파일을 고정한다. #11의 Kakao 결과를 GPT·전화에 전달할 수 있는 범위를 확인한다.
2. Pleos 목적지 모델과 세대 무효화를 제품 앱에 붙인다. ETA 시간 의미·응답 연관성은 기기에서 검증되기 전 예약 시각으로 변환하지 않는다.
3. Kakao 후보·GPT 근거·전화 질문/응답을 합치는 추천 작업을 서버에 구현한다. 실패·0건·필수 UNKNOWN을 구분하고 폴링은 외부 호출을 재실행하지 않는다.
4. Gleo 음성 명령과 완료 TTS를 붙인다. Gleo Action은 7초 안에 접수·실패를 반환하고 장기 작업은 앱이 별도로 조회한다.
5. 선택·승인→전화 예약→결과 대조를 붙인다. 후보 순번만으로 매장 ID를 만들지 않는다.
6. 10분 ETA 점검과 지연 통보를 붙인다. 지연 임계값과 반복 통보 정책을 확정하고 원 예약을 보존한다.
7. 각 단계에서 가상 통합 테스트 후 실제 기기·외부 API·전화 시험을 별도 증거로 기록한다.

## 지금 막히는 결정

- #1: Pleos ETA의 시간 기준과 현재 경로 연관성, 갱신 주기.
- #11: Kakao 원문/가공 결과의 GPT 전송, 전화 전달, 임시 보관 범위.
- #43: 조건 문의와 지연 통보의 실제 API 및 LIVE 보호 경계.
- 제품 정책: 사용자가 지연 때마다 연락 여부를 결정한다. 예약 승인과 지연 연락 승인을 별도 값으로 관리하며 승인 없는 실제 지연 발신은 하지 않는다. 같은 지연을 반복해서 묻지 않도록 요청 세대를 기록한다.

실제 전화·유료 GPT 호출은 대상·횟수·비용 상한을 정한 승인 범위에서만 실행한다.

## 현재 구현 진행

- 웹추천 요청의 `HIGH_CHAIR`·`STEP_FREE_ACCESS`를 기존 `CHILD_FRIENDLY`와 분리했다. 명시적 근거가 없으면 UNKNOWN으로 두며 전화 문의 대상이다. 실제 GPT 모델/계정 호출 검증은 하지 않았다.
- 추천 계획·미리보기 계약도 `highChair`·`stepFreeAccess`를 별도 필수 조건과 전화 확인 질문으로 수용한다. 웹사이트 상세 정보만으로 이 두 조건을 충족 처리하지 않으며 직접 확인이 남는다.
- GPT 웹추천의 일회성 permit에 출력 토큰 상한을 명시할 수 있게 했다(기본 3072, 허용 256~3072). 저비용 가상 검증은 1024 한도를 쓰는 요청 본문을 확인했다.
- 사용자 승인 범위에서 `gpt-6-luna` Responses API를 가상 서울 목적지·주차 조건으로 HTTP 요청 **1회** 실행했다. `store=false`, `max_output_tokens=1024`, `max_tool_calls=1`, 웹검색 문맥 low, 재시도 없음이었다. HTTP 200/완료, 입력 13,080·출력 534토큰(추론 517), 응답 내 `web_search_call` 항목 2개였다. 이 항목 수는 청구되는 검색 횟수와 같다고 단정하지 않는다. 결과의 주차는 UNKNOWN이고 인용 주석은 0개이며 URL도 HTTP라 제품 파서는 이를 검증된 추천으로 수용하지 않는다. 실제 매장·응답 원문·API 키를 저장소에 남기지 않았다. 추가 GPT 호출은 하지 않았다.
- 공공 catalog의 내부 목적지 검색과 비동기 폴링을 합친 `PublicDestinationRecommendationService`를 추가했다. 아직 제품 HTTP/앱·실제 catalog·GPT/전화 경로에 연결하지 않았고 시범 지역 밖은 실패로 처리한다.
- 제품 Android 앱에 명시적 Pleos 목적지 조회·화면 표시·경로 이벤트 무효화 경계를 넣었다. 아직 SDK 응답 연관성 미검증으로 실제 추천/예약 입력에는 사용하지 않으며 로컬 SDK 부재로 Android 빌드/기기 검증은 미완료다.
- 서버 `RecommendationJobRegistry`의 메모리 작업 상태·소유권·세대 취소·완료 결과 폴링 경계를 추가했다. 실제 검색 worker와 HTTP 계약은 아직 붙지 않았다. 전화 AI 계약 제안은 #43에 남겼으며 답변 전이다.
- #48/PR #49의 로컬 공공 catalog 준비 코드를 격리 브랜치에 가져왔다. 별도 승인된 웹 출처 조사는 이 공공 출처 후보에만 허용하고 Kakao 후보는 차단하는 내부 연결을 추가했다. 실제 catalog 취득·제품 주입·유료 GPT 검색·전화 전송은 하지 않았다.
- `DestinationRecommendationState`는 SDK 비의존 목적지 관측과 추천 작업 세대를 보관한다. 경로 취소/변경·재관측·새 요청 이후 이전 추천 결과를 현재 값으로 적용하지 않는 경계만 구현했으며 제품 앱과 SDK 연결은 남았다. SDK 콜백의 원 요청 연관성을 이 상태 경계만으로 보장하지 않는다.
- #50/#43/#16/#26/#1 Draft 소스를 격리 통합 브랜치에 반영했다. 각 원래 PR의 병합이나 팀 인수를 의미하지 않는다.
- 서버의 `DelayContactPolicy`는 검증된 절대 ETA가 확정 예약 시각보다 10분 이상 늦을 때 `ASK_USER`를 반환한다. 마지막 확인 후 10분 미만이면 새 판단을 하지 않고, 이미 물은 ETA보다 10분 미만으로 더 늦어진 같은 지연은 다시 묻지 않는다. 이 순수 판단기는 발신·저장·주기 실행을 하지 않는다.
