# 새 UI의 EC2 시험 번호 연결

2026-11-12. 원격 main `e9ea91f`, 병합된 PR #64 `d57f49a`의 앱용 계약과 gateway 코드를 읽고 필요한 클라이언트 연결을 기존 작업 트리에 적용했다. 기존 작업을 리셋하거나 main을 병합하지 않았다. 기본 빌드는 MOCK이며 실제 연결은 명시적 paired debug 빌드로 분리된다.

## 구현

- `FinalReservationActivity`의 디자인/단계 구성을 유지하고 `pairedPhoneDemo`에서 EC2 `https://43.201.115.170/pleos-phone`에 직접 연결한다. SSH 터널을 사용하지 않는다.
- 새 앱 ID `ai.pleos.assistant.pairedphone`. 같은 익명 인증으로 코드 발급, 등록 상태, 실제 추천, 선택/승인, 통화 결과를 조회한다. Swagger 로그인과 앱 인증은 별개이며 코드로 소유자를 연결한다.
- 내비 SDK 목적지 이름/좌표를 수신한다. 현재 경로 응답 연관성은 여전히 UNVERIFIED이며, 사용자에게 목적지 대조와 고정 시연 확인을 요구한다. 목적지 변화/화면 이탈 시 기존 후보를 무효화한다. 실제 ETA는 연결하지 않았다.
- LIVE 검색 버튼은 유료 웹검색 가능성을 안내한다. 승인 화면은 후보, 인원, 날짜, 희망 시각, 가상 예약자 이름, 번호 끝자리, 모드, 최대60초·과금 가능성을 표시한다. 실제 식당 번호를 앱에서 주입하지 않는다.
- 발신 전 원 요청과 idempotency key를 로컬에 저장한다. 중복 승인과 재시작 후 자동 재발신은 차단한다. 서버 결과 ID가 저장한 요청 key와 다른 경우 결과를 확정으로 표시하지 않는다. 재실행·수동 조회·주기 조회는 GET이다.
- LIVE 음성 검색은 이번 시연 경로에서 차단하고 버튼으로만 실행한다. 음성 인원 입력 자체는 검색/발신 권한이 아니다.

## 사용자 실행 순서

1. 앱에서 연결 코드를 발급한다(5분 유효, 일회용).
2. `https://43.201.115.170/phone-test/docs/`의 **Pleos 앱 시험 번호 연결**에 코드·개발자 번호·LIVE를 입력한다. 기존 브라우저 번호 등록은 이 연결을 대체하지 않는다.
3. 앱에서 등록 번호 끝자리/LIVE 표시를 확인한다. 내비 목적지와 화면의 이름을 대조하고 ‘이 목적지로 시연 검색 허용’을 누른다.
4. 성인/아이/필수 조건을 정하고 검색 버튼을 누른다. 실제 공급자 결과 수만큼 표시하며 3개를 보장하지 않는다.
5. 후보를 선택하고 승인 내용을 확인한 뒤 **등록 번호 전화 시험 승인**을 누른다. 최대60초·공급자 과금 가능성에 동의한 사용자 클릭으로 실행한다.
6. 개발자 전화에서 식당 역할로 응답하고 앱 결과를 조회한다. 빈자리/조건 확인만으로 확정하지 않으며 최종 수락이 부족하면 UNKNOWN을 유지한다.

등록은 1시간, 연결당 검색/전화 각3회 등 서버 제한이 있다. 발신 요청 후 초기화로 다시 발신을 우회하지 않는다. 이전 MOCK의 시연 초기화 정책과 실전화의 미확인 요청 보존을 구분한다.

- `verifyAll`, `verifyAndroid`, 계측 APK 빌드 PASS. 주야간 대비 및 Android Lint 포함.
- Pleos 에뮬레이터 `PAIRED_VIEW` 검사: **가상 응답 주입**으로 코드 화면·UNKNOWN/CONFIRMED 구분·결과 표시·변경 미지원 안내 PASS. 실제 추천/전화 API 시나리오 검증으로 세지 않는다.
- 실제 EC2 익명 세션 생성과 등록 상태 조회까지 확인했다. 새 UI에서 SDK 목적지 수신도 확인했다. 이후 아래 LIVE 재연결 검증을 진행했다. 에이전트의 실제 검색/발신은 0회다.
- 증거 `work/final-live/connection-ready.png`, `build.log`, `device.log`, `final-build.log`, `smoke.log`. 사용자에게 실제 실행을 넘긴다. 이슈 게시·push 없음.

## 예약 변경이 아직 연결되지 않은 이유

`api/pleos-phone-test.openapi.json`과 main의 `prototypes/phone_agent/paired_phone.py`에서 확인한 앱용 경로는 연결 코드/상태/해제와 calls POST/GET뿐이다. `CallResult.id`는 attempt ID이며 내부 bookingId를 대신해서 예약 변경에 사용할 수 없다. 내부 bookingId, 대화 내역, 회신 제안, 결정/변경 요청 API는 앱용 응답에 없다.

따라서 브라우저 `/api/action`을 별도 소유자로 호출해 같은 예약이라고 취급하지 않는다. 실제 예약 변경/회신/대화 API 연결은 **미완료**이며 임의의 endpoint나 성공 상태를 만들지 않았다. 서버 담당자가 앱 Bearer 소유자 아래 같은 booking을 조회하고 다음을 제공해야 연결할 수 있다.

- 회신·변경 제안 조회: 원 시각, 제안 시각/비용, 사유, 제안 ID/버전, 기한과 상태.
- 사용자 변경 요청 또는 제안 수락/거절: 같은 예약 소유권, 중복 방지 키, 버전 충돌 규칙.
- 식당 재확인 결과와 대화 조회: 명시적 수락 및 시각·비용 일치 전 원 예약 유지, UNKNOWN 조회 복구.

실전화 성공·실제 식당 추천·변경 완료·공동 인수는 이번 작업으로 통과 처리하지 않는다.

## 시연 직전 MOCK 오연결 수정 (2026-11-12)

- 원인: 열린 phone-test Swagger의 앱 연결 등록 요청/200 응답 모두 mode=MOCK였다. 서버는 mode 생략 시에도 MOCK이며 가상 후보와 모의 CONFIRMED를 반환한다. 앱이 이를 실제 발신으로 오인하게 허용한 문제를 수정했다.
- LIVE·active·유효기간·번호 끝자리 확인 전 검색/승인 차단. MOCK 결과는 실제 예약 확정으로 표시하지 않는다. 완료된 동일 MOCK 요청만 로컬 발신 잠금에서 제외하며 LIVE/UNKNOWN 요청은 보존한다.
- verifyAll, verifyAndroid PASS. Pleos PAIRED_VIEW 계측: MOCK 연결 차단, LIVE UNKNOWN/CONFIRMED 표시 PASS(주입 응답 UI 검사).
- 기존 MOCK 연결 해제 후 동일 등록 시험 번호를 LIVE로 재등록했다. 서버200 active=true/mode=LIVE 응답 및 앱의 LIVE 조건 화면을 확인했다. 현재 내비 수신 목적지는 판교역 신분당선. ETA25분은 여전히 시연값이다.
- 실제 유료 검색/전화는 이번 수정 검증에서 실행하지 않았다. 사용자의 목적지 확인→검색→선택→발신 승인→전화 수신/결과 확인이 남았다. LIVE 등록 성공을 실통화 성공으로 세지 않는다.
- 예약 변경·대화 조회 앱용 API 부재는 위 제한과 같다. 이슈 게시/커밋/push 없음.

### 2026-11-12 새 시연 시작

개발 도구에 ‘새 시연 처음부터 시작’ 추가. LIVE CONFIRMED(확정 시각 포함)/DECLINED와 원 요청 ID가 일치할 때만 발신 잠금을 정리하고 이전 결과 ID를 로컬에 저장하여 이후 GET/재실행 시 같은 결과를 다시 열지 않는다. 새 결과와 UNKNOWN은 숨기지 않는다. 진행 중/결과 없음의 미해결 요청은 초기화 불가. 예약 요청이 없는 초기 화면에서는 조건만 초기화한다. 서버 예약 취소·기록 삭제·자동 검색/발신 없음; 인증과 LIVE 등록을 유지한다. verifyAndroid 및 Pleos PAIRED_VIEW 계측(가상 응답: UNKNOWN 차단, 완료 초기화, 늦은 동일 결과 숨김, 다른 결과 보존) PASS. 실제 발신은 실행하지 않았다.

### 2026-11-12 가상 변경 연락 알림

사용자 요청으로 개발 도구에 ‘가상 연락 · 20분 지연 알림 띄우기’를 추가. LIVE 확정 결과가 있을 때 현재 확정 시각+20분(자정 경계는 다음 날 표시)을 인앱 모달로 제안한다. 변경 수락/기존 시간 유지/나중에 선택, 시연용 가상 연락 표시. 선택 결과는 해당 예약 ID에만 메모리 표시하며 실제 서버 상태·시각·발신 journal은 수정하지 않는다. 실제 수신/변경 API 연결이 아니며 앱 재실행 시 가상 표시가 사라진다. 주행 입력 제한 또는 UNKNOWN에서는 실행하지 않고 화면 종료 시 모달을 닫는다.

verifyAndroid·계측 APK 빌드 PASS. Pleos PAIRED_VIEW 주입 응답 검사에서 19:10→19:30 알림 표시, 수락/유지 처리 함수의 결과 표시와 서버 JSON 불변, UNKNOWN 차단 PASS. 실제 변경·전화·유료 검색0회. 알림은 시스템 푸시/실전화 수신이 아닌 앱 내 시연 모달이다.
